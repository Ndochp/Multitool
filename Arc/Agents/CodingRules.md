# Правила построения обработки интеграции с внешними системами

## 1. Общие принципы

### 1.1 Гексагональная архитектура
Все интеграции строятся по принципам гексагональной (шестиугольной) архитектуры:
- **Доменный слой** — обработка-клиент, оперирующая бизнес-сущностями (Сотрудник, НоменклатурнаяГруппа, Задача). Не знает о технических деталях API.
- **Адаптеры** — отдельные модули для транспорта, аутентификации, сериализации. Легко заменяются.
- **Порты** — контракты (наборы экспортных методов), определяющие взаимодействие между слоями.

### 1.2 Разделение ответственности
| Слой | Ответственность | Реализация |
|------|-----------------|------------|
| Транспортный адаптер | HTTP-запросы, пул соединений, таймауты | КоннекторHTTP (внешняя библиотека) |
| Адаптер аутентификации | Токены, заголовки авторизации, обновление токенов | Общий модуль `ИнтеграцияАутентификация*` |
| Сериализатор | JSON/XML преобразование | Общий модуль `ИнтеграцияСериализаторJSON` |
| Доменный сервис (обработка) | Бизнес-логика интеграции, маппинг сущностей | Обработка-клиент (`Интеграция*`) |

### 1.3 Чистый бизнес-интерфейс
Публичные методы обработки должны оперировать **только бизнес-сущностями**:
- Вход: ссылки на справочники (Сотрудник, НоменклатурнаяГруппа и т.д.)
- Выход: структуры с бизнес-полями (Сотрудник, Проект, Задача, Длительность)
- Технические ID внешних систем (GitLab User ID, Project ID) скрыты внутри

## 2. Структура обработки интеграции

### 2.1 Метаданные обработки
```
Обработка "Интеграция[ИмяСистемы]"
├── Ext/
│   ├── ObjectModule.bsl      # Модуль объекта: публичный API + внутренние методы
│   └── ManagerModule.bsl     # Фабричные методы (СоздатьИнтеграцию)
```

### 2.2 Реквизиты обработки (состояние)
| Имя | Тип | Назначение |
|-----|-----|------------|
| БазовыйURL | Строка | URL внешней системы |
| Токен | Строка | Токен аутентификации |
| Кэш[Имя] | Соответствие | Кэш маппингов сущностей (ленивая загрузка) |

### 2.3 Область программного интерфейса (`#Область ПрограммныйИнтерфейс`)
Все публичные экспортные методы размещаются в области `#Область ПрограммныйИнтерфейс`:

```bsl
// УстановитьБазовыйURL(Знач БазовыйURL) Экспорт
// УстановитьТокен(Знач Токен) Экспорт
// Получить[Данные](Сотрудник, ДатаНач, ДатаКон) Экспорт
```

### 2.4 Область служебных методов (`#Область СлужебныеПроцедурыИФункции`)
Все внутренние методы — в области `#Область СлужебныеПроцедурыИФункции`:

```bsl
// СформироватьURL(Эндпоинт)
// ПроверитьИнициализацию()
// ПолучитьЗаголовкиАутентификации()
// ВыполнитьЗапросСАвторизацией(Метод, Путь, Тело)
// Преобразовать[Данные]ВБизнес(СырыеДанные)
// Преобразовать[Данные]ИзБизнес(БизнесДанные)
```

## 3. Паттерны реализации методов

### 3.1 Инициализация
```bsl
Процедура УстановитьБазовыйURL(Знач БазовыйURL) Экспорт
    ЭтотОбъект.БазовыйURL = БазовыйURL;
КонецПроцедуры

Процедура УстановитьТокен(Знач Токен) Экспорт
    ЭтотОбъект.Токен = Токен;
КонецПроцедуры
```

### 3.2 Публичный метод с бизнес-интерфейсом
```bsl
Функция ПолучитьЗаписиВремениПоСотруднику(Сотрудник, ДатаНач, ДатаКон) Экспорт
    // 1. Маппинг бизнес-сущности → технический ID (с кэшем)
    ВнешнийID = ПолучитьВнешнийID(Сотрудник);
    
    // 2. Формирование запроса к API
    Путь = СформироватьПутьДляЗапроса(ВнешнийID, ДатаНач, ДатаКон);
    
    // 3. Выполнение запроса с авторизацией и повтором при 401
    Ответ = ВыполнитьЗапросСАвторизацией("GET", Путь);
    
    // 4. Проверка кода состояния
    Если Ответ.КодСостояния <> 200 Тогда
        ОбработатьОшибкуОтвет(Ответ);
    КонецЕсли;
    
    // 5. Преобразование ответа в бизнес-структуры
    Возврат ПреобразоватьЗаписиВБизнес(Ответ.Тело);
КонецФункции
```

### 3.3 Внутренний метод маппинга с кэшированием
```bsl
Функция ПолучитьВнешнийID(Сотрудник)
    // Проверка кэша
    Если КэшСотрудник_ВнешнийID.Содержит(Сотрудник) Тогда
        Возврат КэшСотрудник_ВнешнийID[Сотрудник];
    КонецЕсли;
    
    // Запрос к БД (первый доступ)
    ВнешнийID = ЗапроситьВнешнийIDИзБД(Сотрудник);
    КэшСотрудник_ВнешнийID.Вставить(Сотрудник, ВнешнийID);
    Возврат ВнешнийID;
КонецФункции

Процедура ЗаполнитьКэшСотрудников(МассивСоответствий) Экспорт
    Для Каждого Стр Из МассивСоответствий Цикл
        КэшСотрудник_ВнешнийID.Вставить(Стр.Сотрудник, Стр.ВнешнийID);
    КонецЦикла;
КонецПроцедуры
```

### 3.4 Централизованная обработка авторизации (паттерн с повтором)
```bsl
Функция ВыполнитьЗапросСАвторизацией(Метод, Путь, Тело = "")
    ПопыткаПовтора = 0;
    
    Пока Истина Цикл
        Заголовки = ПолучитьБазовыеЗаголовки();
        
        Ответ = ВыполнитьHTTPЗапрос(Метод, Путь, Тело, Заголовки);
        
        Если Ответ.КодСостояния = 401 И ПопыткаПовтора = 0 Тогда
            // Обновление токена
            НовыйТокен = ИнтеграцияАутентификация.ОбновитьТокен(ЭтотОбъект.Токен);
            Если ЗначениеЗаполжено(НовыйТокен) Тогда
                ЭтотОбъект.Токен = НовыйТокен;
                ПопыткаПовтора = 1;
                Продолжить;
            КонецЕсли;
        КонецЕсли;
        
        Возврат Ответ;
    КонецЦикла;
КонецФункции
```

## 4. Структуры данных ответа

### 4.1 Бизнес-структуры вместо технических
❌ **Плохо** (торчит внешняя система):
```bsl
// user → id, project_id, issue → iid, spent_at, summary
```

✅ **Хорошо** (бизнес-термины):
```bsl
// Структура "ЗаписьТаймшита":
//   Сотрудник (Справочник.Сотрудники)
//   НоменклатурнаяГруппа (Справочник.Номенклатура)
//   Задача (Справочник.Задачи — ссылка, может быть Неопределено)
//   ДлительностьВСекундах (Число)
//   Дата (Дата)
//   Комментарий (Строка)
//   ИдентификаторЗаписи (Число — техническое поле для обновления)
```

### 4.2 Возврат данных
- Предпочтительно: **ТаблицаЗначений** с описанными колонками
- Или: **Массив структур** с именованными полями
- Типы колонок должны быть явно заданы через `ОписаниеТипов`

## 5. Аутентификация

### 5.1 Базовые правила
- Токен хранится в реквизите обработки (состояние)
- Заголовки формируются в методе `ПолучитьЗаголовкиАутентификации()`
- Для GitLab: заголовок `PRIVATE-TOKEN`

### 5.2 Короткоживущие токены
Для систем с refresh-token механизмом:
1. Адаптер аутентификации должен иметь метод `ОбновитьТокен(ТекущийТокен)`
2. Метод `ВыполнитьЗапросСАвторизацией` вызывает обновление при 401
3. Максимум одна попытка повтора (защита от бесконечного цикла)

## 6. Тестирование

### 6.1 Правила для yaxUnit
- Код обработки должен быть совместим с перегрузкой методов в тестовом расширении
- Не использовать `Новый` внутри методов для создания зависимостей
- Все HTTP-вызовы — через КоннекторHTTP (перегружается в тестах)

### 6.2 Пример тестовой подмены
```bsl
// В тестовом расширении:
Процедура Мок_Get(URL, ПараметрыЗапроса, ДополнительныеПараметры, Сессия) Экспорт
    // Возврат фиктивного JSON-ответа
КонецПроцедуры
```

## 7. Производительность

### 7.1 Кэширование
- Использовать реквизиты обработки для кэша маппингов сущностей
- Ленивая загрузка: запрос к БД только при первом обращении
- Метод `ЗаполнитьКэш[Сущности]()` для предзагрузки

### 7.2 HTTP-соединения
- Пул соединений делегируется КоннекторHTTP (keep-alive)
- Таймауты задаются в каждом вызове HTTP-запроса

## 8. Обработка ошибок

### 8.1 Универсальный обработчик
```bsl
Процедура ОбработатьОшибкуОтвет(Ответ)
    Код = Ответ.КодСостояния;
    Тело = КоннекторHTTP.КакТекст(Ответ);
    
    Если Код = 401 Тогда
        ВызватьИсключение "Не авторизован. Проверьте токен.";
    ИначеЕсли Код = 403 Тогда
        ВызватьИсключение "Доступ запрещён.";
    ИначеЕсли Код = 404 Тогда
        ВызватьИсключение "Ресурс не найден.";
    Иначе
        ВызватьИсключение String(Код) + ": " + Тело;
    КонецЕсли;
КонецПроцедуры
```

## 9. Фабричные методы

### 9.1 ManagerModule
Фабричный метод в `ManagerModule.bsl`:
```bsl
Функция СоздатьИнтеграцию(Знач БазовыйURL = "", Знач Токен = "") Экспорт
    Интеграция = Обработки.Интеграция[Имя].СоздатьОбъект();
    
    Если ЗначениеЗаполнено(БазовыйURL) Тогда
        Интеграция.УстановитьБазовыйURL(БазовыйURL);
    КонецЕсли;
    
    Если ЗначениеЗаполнено(Токен) Тогда
        Интеграция.УстановитьТокен(Токен);
    КонецЕсли;
    
    Возврат Интеграция;
КонецФункции
```

## 11. Чек-лист при создании новой интеграции

- [ ] Создана обработка `Интеграция[Имя]` с модулями ObjectModule и ManagerModule
- [ ] Публичный API использует бизнес-сущности (не внешние ID)
- [ ] Реализован кэш маппингов в реквизитах обработки
- [ ] Метод `ВыполнитьЗапросСАвторизацией` обрабатывает 401 с обновлением токена
- [ ] Структуры ответа содержат бизнес-поля (Сотрудник, Проект, Задача)
- [ ] Метод `ПроверитьИнициализацию()` проверяет базовый URL и токен
- [ ] Метод `ОбработатьОшибкуОтвет()` универсально обрабатывает HTTP-ошибки
- [ ] Фабричный метод `СоздатьИнтеграцию()` в ManagerModule
- [ ] Код совместим с yaxUnit (нет жёстких зависимостей от внешних компонентов)
