# GitLab.mirror — Схема справочников

Проекция сущностей GitLab в справочники 1С. Зеркало — **только чтение**: данные
создаются/обновляются исключительно синхронизацией через GitLab API
(обработка `ИнтеграцияGitlab`), пользователю прямое редактирование не нужно.

## Общие принципы

| Принцип | Решение |
|---|---|
| Префикс имён | `Гитлаб…` (в стиле `ИнтеграцияGitlab`, `ТаймлогиGitlab`), синоним «GitLab: …» |
| Подсистема | Все объекты включаются в `GitLabMirror` |
| Связь с GitLab | Реквизит `Идентификатор` (Число) — глобальный `id` из API |
| Код справочника | = идентификатор из GitLab (строка). У подчинённых — уникален в рамках владельца (это ровно соответствует IID задач и id меток проекта) |
| Владение | Project → Issue → Note; Project → Label. Timelog — независимый |
| Ссылочные поля | Пустая ссылка, если сущность не отзеркалена (не ошибка) |
| Даты | UTC GitLab сохраняется как есть (Дата с временем) |

## Реализуемые справочники

### 1. ГитлабПользователи (GitLab: Пользователи) — независимый

User → `/api/v4/users/:id`. Код = `id`.

| Реквизит | Тип | Источник API |
|---|---|---|
| Идентификатор | Число | `id` |
| ИмяПользователя | Строка(100) | `username` |
| ПолноеИмя | Строка(150) | `name` |
| Email | Строка(150) | `email`/`commit_email` (может быть пусто) |
| ВебURL | Строка(250) | `web_url` |
| АватарURL | Строка(250) | `avatar_url` |
| Заблокирован | Булево | `state = "blocked"` |
| ДатаСоздания | Дата | `created_at` |

Наименование = `ПолноеИмя (ИмяПользователя)`.

### 2. ГитлабПроекты (GitLab: Проекты) — независимый

Project → `/api/v4/projects/:id`. Код = `id`.
Репозиторий неотделим от проекта, поэтому его URL и ветка по умолчанию —
реквизиты здесь (отдельный справочник `ГитлабРепозитории` описан ниже, пригодится
при зеркалировании веток/тегов).

| Реквизит | Тип | Источник API |
|---|---|---|
| Идентификатор | Число | `id` |
| ПутьПолный | Строка(200) | `path_with_namespace` (уникальный ключ человека) |
| Путь | Строка(100) | `path` |
| ВебURL | Строка(250) | `web_url` |
| Описание | Строка(0) | `description` |
| РепозиторийHTTP | Строка(250) | `http_url_to_repo` |
| РепозиторийSSH | Строка(250) | `ssh_url_to_repo` |
| ВеткаПоУмолчанию | Строка(100) | `default_branch` |
| Видимость | Строка(20) | `visibility` (private/internal/public) |
| Архивный | Булево | `archived` |
| ДатаСоздания | Дата | `created_at` |
| ПоследняяАктивность | Дата | `last_activity_at` |

Наименование = `name`.

### 3. ГитлабМетки (GitLab: Метки) — подчинён ГитлабПроекты

Label → `/api/v4/projects/:id/labels`. Код = `id` метки.
Групповые метки (group labels) отражаются как элементы, подчинённые конкретному
проекту, с флагом `ЭтоГрупповая`.

| Реквизит | Тип | Источник API |
|---|---|---|
| Идентификатор | Число | `id` |
| Имя | Строка(150) | `name` |
| Цвет | Строка(20) | `color` (#RRGGBB) |
| Описание | Строка(0) | `description` |
| ЭтоГрупповая | Булево | в ответе есть `group_id` |
| Приоритет | Число | `priority` |

Наименование = `name`.

### 4. ГитлабЗадачи (GitLab: Задачи) — подчинён ГитлабПроекты

Issue → `/api/v4/issues` (глобальный список с отборами), `project_id` известен из
ответа. Код = `iid` (уникален в проекте).

| Реквизит | Тип | Источник API |
|---|---|---|
| Идентификатор | Число | `id` (глобальный) |
| Состояние | Строка(20) | `state` (opened/closed) |
| Автор | ГитлабПользователи | `author.id` |
| Описание | Строка(0) | `description` |
| ДатаСоздания | Дата | `created_at` |
| ДатаОбновления | Дата | `updated_at` |
| ДатаЗакрытия | Дата | `closed_at` |
| ВебURL | Строка(250) | `web_url` |
| Дедлайн | Дата | `due_date` |
| Вес | Число | `weight` |
| ОценкаВремени | Число | `time_stats.time_estimate` (сек) |
| ЗатраченоВремени | Число | `time_stats.total_time_spent` (сек) |

Табличные части:

| ТЧ | Колонки | Источник |
|---|---|---|
| Метки | Метка (ГитлабМетки), Имя (Строка) | `labels[]`, `label_details` |
| Исполнители | Пользователь (ГитлабПользователи) | `assignees[]` |

Наименование = `title`.

### 5. ГитлабЗаписиВремени (GitLab: Записи времени) — независимый

Timelog → `/api/v4/projects/:id/issues/:iid/timelogs`, `/users/:id/time_entries`.
Код = `id` timelog.

| Реквизит | Тип | Источник API |
|---|---|---|
| Идентификатор | Число | `id` |
| Проект | ГитлабПроекты | `project.id` |
| Задача | ГитлабЗадачи | `issue.id` |
| Пользователь | ГитлабПользователи | `user.id` |
| ДатаЗаписи | Дата | `spent_at` |
| ДлительностьСекунд | Число | `time_spent` / `duration` |
| СуммаВремени | Строка(50) | `human_time_estimate`/`summary` |
| Описание | Строка(0) | `summary` / `note` |

### 6. ГитлабКомментарии (GitLab: Комментарии) — подчинён ГитлабЗадачи

Note → `/api/v4/projects/:id/issues/:iid/notes`. Код = `id` note.

| Реквизит | Тип | Источник API |
|---|---|---|
| Идентификатор | Число | `id` |
| Автор | ГитлабПользователи | `author.id` |
| Текст | Строка(0) | `body` |
| Системный | Булево | `system` ( служебные записи о смене меток и пр.) |
| ДатаСоздания | Дата | `created_at` |
| ДатаОбновления | Дата | `updated_at` |
| ТипОбсуждения | Строка(50) | `type` (DiscussionNote и т.п.) |

Наименование = первые ~100 символов `body`.

## Описанные, но не реализуемые в этой итерации

Эти сущности пригодятся на следующих шагах направления; схема фиксируется сейчас,
чтобы не менять реализованные объекты.

| Сущность GitLab | Справочник 1С | Владение | Ключевые реквизиты |
|---|---|---|---|
| Repository (отдельная сущность при зеркалировании веток/тегов) | ГитлабРепозитории | ГитлабПроекты | ВеткаПоУмолчанию, URLHTTP, URLSSH, РазмерБайт |
| Branch | ГитлабВетки | ГитлабРепозитории | Имя, ПоследнийКоммит(Идентификатор) |
| Commit | ГитлабКоммиты | ГитлабРепозитории | Хеш (Код), Автор, Сообщение, ДатаКоммита, РодительскиеХеши |
| Pipeline (запуск пайплайна, не yaml) | ГитлабПайплайны | ГитлабПроекты | Идентификатор, Iид, Хеш, Ветка, Статус, ДатаНачала, ДатаОкончания, ДлительностьСекунд, ВебURL, Запустил(ГитлабПользователи) |
| Pipeline job | ГитлабЗаданияПайплайна | ГитлабПайплайны | Идентификатор, Этап, Статус, Стенд, ДлительностьСекунд |
| Merge request | ГитлабЗапросыСлияния | ГитлабПроекты | Iид, Источник/Приёмник(ветка), Статус, Автор, Исполнитель |
| Group / Namespace | ГитлабГруппы | независимый | Идентификатор, ПутьПолный, Родитель |

## Поток данных (шаг 3)

```
ИнтеграцияGitlab (REST GET /api/v4/issues?labels=…)      ← адаптер (порты)
        │ таблица значений
        ▼
ГитлабЗеркало (общий модуль подсистемы GitLabMirror)      ← синхронизация (ядро)
        │ ОбеспечитьПроект / ОбеспечитьПользователя /
        │ ОбеспечитьМетку / ОбеспечитьЗадачу / ОбеспечитьКомментарии / ОбеспечитьЗаписьВремени
        ▼
Справочники Гитлаб… (зеркало, write-only из синхронизации)
```

Точка входа: `ГитлабЗеркало.ЗеркалироватьЗадачиПоМетке(Интеграция, Метка)` —
читает задачи GitLab с отбором по метке (например «отв: НД»), догружает
справочники владельцев (проекты, пользователи, метки) и записывает задачи.
