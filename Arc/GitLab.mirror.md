# GitLab.mirror — Роли и юзкейсы

## Роли

### Сотрудник
Пользователь, который просматривает свои записи времени (timelogs), созданные в других системах (например, Jira), или добавляет свои записи в GitLab.

### Менеджер / Руководитель
Пользователь, который просматривает статистику затраченного времени членов команды на проектах и задачах GitLab для анализа загрузки и отчётности.

### Администратор
Пользователь, который настраивает подключение подсистемы к GitLab (базовый URL, токен аутентификации) и управляет персональными токенами сотрудников.

---

## Юзкейсы

### UC-01: Просмотр своих таймлогов

**Роль:** Сотрудник  
**Предусловие:** Подсистема GitLab.mirror подключена к корпоративному GitLab, токен аутентификации сотрудника настроен.  
**Основной поток:**
1. Сотрудник открывает форму «ТаймлогиGitLab».
2. В поле «Сотрудник» выбирает себя (или значение подставляется автоматически).
3. В полях «Дата» указывает период (конкретную дату или диапазон дат начала/окончания).
4. Нажимает «Выполнить поиск».
5. Система отображает таблицу с таймлогами сотрудника за указанный период: ID записи, проект, задача, дата/время начала, длительность, описание, веб-ссылка.

**Постусловие:** Таблица результатов содержит все найденные таймлоги сотрудника за указанный период.

### UC-02: Удаление таймлога

**Роль:** Сотрудник  
**Предусловие:** Таймлог сотрудника отображается в таблице формы «ТаймлогиGitLab».  
**Основной поток:**
1. Сотрудник выделяет строку с нужным таймлогом в таблице результатов.
2. Нажимает кнопку «Удалить выбранную запись».
3. Система показывает диалог подтверждения удаления.
4. Сотрудник подтверждает удаление.
5. Система отправляет DELETE-запрос на эндпоинт `/projects/{id}/issues/{iid}/timelogs/{timelog_id}` GitLab API.
6. Система обновляет таблицу результатов.

**Постусловие:** Таймлог удалён из GitLab, таблица результатов обновлена.

### UC-03: Открытие задачи в GitLab

**Роль:** Сотрудник  
**Предусловие:** Таймлог отображается в таблице формы «ТаймлогиGitLab».  
**Основной поток:**
1. Сотрудник выделяет строку с таймлогом.
2. Нажимает кнопку «Открыть веб-страницу задачи».
3. Система открывает браузер по URL из колонки «Веб-ссылка» (ссылка на задачу в GitLab).

**Постусловие:** Задача открыта в браузере сотрудника.

### UC-04: Экспорт таймлогов в Excel

**Роль:** Сотрудник  
**Предусловие:** Таблица результатов формы «ТаймлогиGitLab» содержит данные.  
**Основной поток:**
1. Сотрудник нажимает кнопку «Экспорт в Excel».
2. Система формирует табличный документ с данными из таблицы результатов.
3. Система предлагает открыть или сохранить файл в формате XLSX.

**Постусловие:** Файл с выгрузкой таймлогов создан.

### UC-05: Просмотр статистики времени по команде

**Роль:** Менеджер / Руководитель  
**Предусловие:** Токены аутентификации членов команды настроены в регистре сведений «НастройкиПользователейGitLab».  
**Основной поток:**
1. Менеджер открывает форму «ТаймлогиGitLab».
2. В поле «Сотрудник» выбирает члена команды (или не указывает — для просмотра всех).
3. В полях «Дата» указывает период анализа.
4. Нажимает «Выполнить поиск».
5. Система отображает таблицу с таймлогами за указанный период.
6. Менеджер анализирует распределение времени по проектам и задачам.

**Постусловие:** Таблица результатов содержит таймлоги для анализа загрузки команды.

### UC-06: Настройка подключения к GitLab

**Роль:** Администратор  
**Предусловие:** Подсистема GitLab.mirror установлена, корпоративный GitLab доступен по сети.  
**Основной поток:**
1. Администратор открывает форму настроек подсистемы GitLab.mirror.
2. В поле «БазовыйURL» вводит адрес GitLab сервера (например, `https://gitlab.company.com`).
3. В поле «Токен доступа» вводит токен аутентификации с правами на чтение timelogs и issues.
4. Нажимает «Проверить подключение».
5. Система выполняет тестовый запрос к GitLab API для проверки подключения.
6. При успешной проверке система сохраняет настройки.

**Постусловие:** Подсистема подключена к GitLab, готова к работе.

### UC-07: Настройка токена сотрудника

**Роль:** Администратор  
**Предусловие:** Подсистема GitLab.mirror подключена к GitLab.  
**Основной поток:**
1. Администратор открывает регистр сведений «НастройкиПользователейGitLab».
2. Создаёт новый элемент регистра.
3. В измерении «Сотрудник» выбирает сотрудника.
4. В ресурсе «ТокенДоступа» вводит персональный токен API сотрудника (с правами на чтение/запись timelogs).
5. Сохраняет элемент.

**Постусловие:** Персональный токен сотрудника настроен, сотрудник может просматривать свои таймлоги.
