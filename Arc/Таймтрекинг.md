# Таймтрекинг — Роли и юзкейсы

## Роли

### Сотрудник (Работник)
Основной пользователь подсистемы таймтрекинга. Ведёт «Лист учёта рабочего времени» — таблицу интервалов работы, переключает задачи в течение дня, синхронизирует записи во внешние системы.

### Администратор
Пользователь, который настраивает подсистему таймтрекинга: определяет задачи по умолчанию, задачу обеда, подключённые внешние системы и права доступа.

## Юзкейсы

### UC-00: Полный сценарий работы с ЛУРВ
роль: Сотрудник
1. Я создаю новый документ ЛУРВ
2. автоматически Дата начала работы заполняется текущей датой. При любом изменении даты начала контролируется, что на эту дату нет других документов ЛУРВ; если есть — рядом с началом работы выводится пометка о существовании другого документа, этот документ не проводится. Автоматизацией интеграции не заниматься. (Задача: [ЛУР-015](Arc/Agents/plan/ТаймтрекингЗадачиРазработки.md#задача-лур-015-документ-листучетарабочеговремени--контроль-дубля-документа-на-дату))
3. автоматически Добавляется первая строка в ТЧ, с датой начала = дате начала дня
4. Когда я меняю дату начала работы - меняется дата начала у первой строки. (и запускаются пересчеты)
5. Если я меняю дату начала строки, то Если эта строка первая, то автоматически меняется дата начала дня. Иначе меняется дата окончания у предыдущей строки и запускаются пересчеты
6. Пересчет при смене даты начала:
	1. Фиксированная длительность - меняется дата окончания, меняется дата начала следующей строки.
	2. обычные строки - если дата окончания становится меньше даты начала, то мы их приравниваем (меняем дату начала следующей строки и запускаем ее пересчет), меняется длительность. 
7. Пересчет при смене даты окончания: 
	1. Для фиксированных строк меняется дата начала, запускается пересчет по смене даты начала
	2. для обычных если дата начала становится больше даты окончания, то они приравниваются, запускается пересчет по изменению даты начала, меняется длительность, 
8. Смена длительности меняет дату окончания, с пересчетом (сменой даты начала следующей строки, если эта строка была последней и конец дня заполнен - смена конца дня)
9. При любой смене реквизитов сравнивается с кэшем данных внешней системы, строка помечается текущим статусом синхронизации
10. Вставка строки в середину табличной части создает строку с нулевой длительностью и датой начала равной дате окончания строки, после которой вставляем
11. Сдвиг строки вниз: приводит к изменению даты начала и окончания строки ниже с сохранением её длительности и смене даты начала и окончания текущей строки с сохранением её длительности
12. Сдвиг строки вверх: аналогично сдвигу вниз, начала и окончания строк меняются, длительности остаются
13. Указание даты окончания дня фиксирует дату окончания последней строки
14. Автоматизация автопродления записи о времени во внешней системе: пока в открытом документе не указана дата окончания последней строки раз в ХХ (по умолчанию 300 секунд) производится корректировка записи о времени для последней строки с длительностью от момента начала до текущей даты.
15. При удалении строки время начала следующей строки становится временем начала удаляемой. (если она обычная, то меняется длительность, если фиксированная, то идет каскадный пересчет вниз). Если у удаляемой строки была привязана запись о времени внешней системы, то она переносится в первую строку таблицы, с датой начала = дата окончания, нулевой длительностью и комментарием "к удалению". 
16. При синхронизации данных об отработанном времени со внешними системами:
	1. сначала получается полный текущий список записей о времени внешней системы. 
	2. Для записей, о которых мы ничего не знаем создаются новые строки, ниже последней строки таблицы. Даты начала и окончания строк заполняются в соответствии с окончанием последней строки и длительностями полученными из внешней системы. Значение времени окончания рабочего дня при необходимости увеличивается. После блока новых строк создается строка "обед" локальной системы. Если день закончен - то с датой окончания рабочего дня, если нет - то с открытой. (нужно чтобы автопродление на начало работать на полученную фиксированную строку внешней системы)
	3. Удаляются записи для строк с нулевой длительностью. При этом строки с комментарием "к удалению" так же удаляются из табличной части
	4. Корректируются записи во внешней системе для отличающихся строк (при необходимости обновляются ИД записей о времени в табличной части)
	5. Создаются записи о времени для строк, которые еще не были привязаны к внешней системе.
### UC-01: Начало рабочего дня

**Роль:** Сотрудник  
**Предусловие:** Документ «ЛистУчетаРабочегоВремени» на текущую дату не создан.  
**Основной поток:** *(соответствует шагам 1–3 UC-00)*
1. Пользователь создаёт новый документ «ЛистУчетаРабочегоВремени» (шаг 1 UC-00).
2. Система автоматически заполняет дату начала работы текущей датой (шаг 2 UC-00).
3. Система добавляет первую строку табличной части с датой начала, равной дате начала дня (шаг 3 UC-00).
4. Система запускает фоновое задание автопродления последней строки (потому, что дата окончания рабочего дня не заполнена).

**Контроль дубля (шаг 2 UC-00):** при заполнении/изменении даты начала работы контролируется, что на эту дату нет других документов ЛУРВ; если есть — рядом с началом работы выводится пометка о существовании другого документа, документ не проводится. Автоматизация интеграции не выполняется.

**Постусловие:** Создан лист учёта рабочего времени с одной строкой и незаполненной датой окончания рабочего дня, запущен процесс автопродления.

### UC-02: Автопродление последней строки

**Роль:** Сотрудник  
**Предусловие:** Документ «ЛистУчетаРабочегоВремени» создан и дата окончания рабочего дня не заполнена.  
**Основной поток:** *(соответствует шагу 14 UC-00)*
1. Пока в открытом документе не указана дата окончания последней строки, фоновое задание автопродления срабатывает каждые ПериодАвтопродления секунд (по умолчанию 300 сек = 5 мин).
2. Система корректирует запись о времени для последней строки: обновляет дату окончания на текущую дату и время, длительность считается от момента начала до текущей даты. Информация передаётся во внешнюю систему.

**Постусловие:** Последняя строка документа актуализирована, длительность текущего интервала отражает реальное время работы.

### UC-03: Переключение задачи (создание новой строки)

**Роль:** Сотрудник  
**Предусловие:** Документ «ЛистУчетаРабочегоВремени» создан и дата окончания рабочего дня не заполнена.  
**Основной поток:**
1. Сотрудник переключается на другую задачу в работе.
2. Создаёт новую строку ниже последней (в конец табличной части) (шаг 10 UC-00).
3. Система фиксирует ВремяОкончания текущей последней строки = ТекущаяДата().
4. Система создаёт новую строку:
   - ВремяНачала новой строки = ВремяОкончания предыдущей строки.
   - Сотрудник выбирает задачу из выпадающего списка (см. UC-04).
5. Новая строка становится последней и начинает автопродление.

**Постусловие:** Предыдущий интервал зафиксирован, создана новая строка с новой задачей.

### UC-04: Выбор задачи при создании/переключении строки

**Роль:** Сотрудник  
**Предусловие:** Требуется выбрать задачу для новой или существующей строки документа «ЛистУчетаРабочегоВремени».  
**Основной поток:**
1. Сотрудник активирует поле выбора задачи (клик или Ctrl+Enter).
2. Система динамически загружает список задач из всех подключённых внешних систем через ФасадИнтеграции.ПолучитьСписокЗадач().
3. Список отображается в выпадающем списке с поиском по подстроке.
4. Сотрудник начинает вводить текст — система фильтрует список и делает повторный запрос к Фасаду.
5. Сотрудник выбирает нужную задачу из отфильтрованного списка.
6. Система кеширует часто используемые задачи на форме для ускорения следующего выбора.

**Постусловие:** Задача выбрана, строка документа связана с задачей.

**Роль:** Сотрудник

**Постусловие:** Все интервалы зафиксированы, заполнена дата окончания рабочего дня, доступна синхронизация.

### UC-06: Ручная правка строк

**Роль:** Сотрудник  
**Предусловие:** Документ «ЛистУчетаРабочегоВремени» открыт.  
**Основной поток:**
1. Сотрудник редактирует ВремяНачала, ВремяОкончания или Комментарий в нужной строке.
2. При любой смене реквизитов системы сравниваются с кэшем данных внешней системы, и строка помечается текущим статусом синхронизации (шаг 9 UC-00): отредактированная строка с интеграцией помечается как требующая пересинхронизации (жёлтый индикатор).
3. При следующей синхронизации старые записи будут удалены и созданы заново с учётом изменений.

**Пересчёты при ручной правке (шаги 4–8 UC-00):**
- **Смена даты начала работы (шаг 4):** меняется дата начала первой строки, запускаются пересчёты.
- **Смена даты начала строки (шаг 5):** если строка первая — автоматически меняется дата начала дня; иначе меняется дата окончания у предыдущей строки и запускаются пересчёты.
- **Пересчёт при смене даты начала (шаг 6):** для фиксированной длительности меняется дата окончания и дата начала следующей строки; для обычной строки — если дата окончания становится меньше даты начала, они приравниваются (меняется дата начала следующей строки и запускается её пересчёт), меняется длительность.
- **Пересчёт при смене даты окончания (шаг 7):** для фиксированной строки меняется дата начала и запускается пересчёт по смене даты начала; для обычной — если дата начала становится больше даты окончания, они приравниваются, запускается пересчёт по смене даты начала, меняется длительность.
- **Смена длительности (шаг 8):** меняется дата окончания с пересчётом; если строка была последней и дата окончания дня заполнена — меняется дата окончания дня.

**Вставка строки в середину (шаг 10 UC-00):**
- Вставка строки в середину табличной части создаёт строку с нулевой длительностью и датой начала, равной дате окончания строки, после которой вставляем.

**Сдвиг строки (шаги 11–12 UC-00):**
- **Сдвиг вниз (шаг 11):** приводит к изменению даты начала и окончания строки ниже с сохранением её длительности, а также к смене даты начала и окончания текущей строки с сохранением её длительности.
- **Сдвиг вверх (шаг 12):** аналогично сдвигу вниз — начала и окончания строк меняются, длительности остаются.

**Удаление строки (шаг 15 UC-00):**
- При удалении строки время начала следующей строки становится временем начала удаляемой (если она обычная — меняется длительность; если фиксированная — идёт каскадный пересчёт вниз).
- Если у удаляемой строки была привязана запись о времени внешней системы, она переносится в первую строку таблицы с датой начала = дата окончания, нулевой длительностью и комментарием «к удалению».

**Постусловие:** Строка отредактирована, помечена как требующая пересинхронизации.

### UC-07: Синхронизация с внешней системой

**Роль:** Сотрудник  
**Предусловие:** Документ «ЛистУчетаРабочегоВремени» содержит строки с задачами, имеющими интеграцию.  
**Основной поток:** *(соответствует шагу 16 UC-00)*
1. Сотрудник нажимает кнопку «Синхронизировать».
2. Система получает полный текущий список записей о времени внешней системы (шаг 16.1 UC-00).
3. Для записей, о которых система ничего не знает, создаются новые строки ниже последней строки таблицы (шаг 16.2 UC-00):
   - даты начала и окончания строк заполняются в соответствии с окончанием последней строки и длительностями, полученными из внешней системы;
   - значение времени окончания рабочего дня при необходимости увеличивается;
   - после блока новых строк создаётся строка «обед» локальной системы: если день закончен — с датой окончания рабочего дня, если нет — с открытой (нужно, чтобы автопродление работало на полученную фиксированную строку внешней системы).
4. Удаляются записи для строк с нулевой длительностью; строки с комментарием «к удалению» также удаляются из табличной части (шаг 16.3 UC-00).
5. Корректируются записи во внешней системе для отличающихся строк (при необходимости обновляются идентификаторы записей о времени в табличной части) (шаг 16.4 UC-00).
6. Создаются записи о времени для строк, которые ещё не привязаны к внешней системе (шаг 16.5 UC-00).
7. При успешной синхронизации строки, соответствующие записям, подсвечиваются зелёным индикатором.

**Обработка ошибок:**
- Если внешняя система недоступна — выводится сообщение, идентификаторы не сбрасываются, строки с ошибкой помечаются жёлтым индикатором.

**Постусловие:** Записи времени синхронизированы с внешней системой, идентификаторы записей актуальны.

### UC-08: Обновление описания записи времени

**Роль:** Сотрудник  
**Предусловие:** Документ «ЛистУчетаРабочегоВремени» содержит строку с заполненным ИдентификаторомЗаписиВремени.  
**Основной поток:**
1. Сотрудник изменяет Комментарий в строке документа.
2. Нажимает кнопку «Обновить описание» (или это происходит автоматически при потере фокуса).
3. Система вызывает `ФасадИнтеграции.ИзменитьЗаписьОВремени(ИдентификаторЗаписиВремени, НовыйКомментарий)`.
4. Для систем без нативной поддержки изменения описания (например GitLab) — Фасад выполняет удаление и создание заново.
5. Система получает новый ИдентификаторОбновленнойЗаписиВремени и обновляет строку документа.

**Постусловие:** Описание записи времени обновлено во внешней системе, идентификатор записи обновлён.

### UC-09: Индикаторы статуса синхронизации строк

**Роль:** Сотрудник  
**Предусловие:** Документ «ЛистУчетаРабочегоВремени» открыт на форме.  
**Основной поток:** *(связан с шагом 9 UC-00)*
1. Система отображает строки документа с цветными индикаторами. При любой смене реквизитов строка сравнивается с кэшем данных внешней системы и помечается текущим статусом синхронизации (шаг 9 UC-00):
   - 🟢 Зелёный — синхронизировано и актуально (ИдентификаторЗаписиВремени заполнен, данные не менялись).
   - 🟡 Жёлтый — требуется синхронизация (идентификатор пуст или данные изменились).
   - ⚪ Серый — не синхронизируется (Обед, локальная задача, ИмеетИнтеграцию = Ложь).

> Примечание: статусы синхронизации относятся только к строкам. У самого документа статусов нет — состояние определяется заполненной или незаполненной датой начала и окончания рабочего дня (см. UC-00).

**Постусловие:** Сотрудник визуально видит статус каждой строки относительно внешней системы.

### UC-10: Настройка задачи по умолчанию и обеда

**Роль:** Администратор  
**Предусловие:** Подсистема таймтрекинга установлена, справочники «ВнешниеЗадачи» и «ТипыВнешнихСистем» заполнены.  
**Основной поток:**
1. Администратор открывает настройки подсистемы таймтрекинга.
2. В реквизите «ЗадачаПоУмолчанию» выбирает элемент справочника «ВнешниеЗадачи» для нераспределённого времени.
3. В реквизите «ЗадачаОбед» выбирает элемент справочника «ВнешниеЗадачи» для обеда.
4. Сохраняет настройки.

**Постусловие:** Новые значения ЗадачаПоУмолчанию и ЗадачаОбед используются при создании нового дня и формировании строки обеда.

### UC-11: Добавление новой внешней системы

**Роль:** Администратор  
**Предусловие:** Подсистема таймтрекинга установлена, уже подключена хотя бы одна внешняя система.  
**Основной поток:**
1. Администратор добавляет новое значение в перечисление «ТипВнешнихСистем» (например, Jira).
2. Создаёт новый модуль API (например, JiraAPI) с методами Добавить/Изменить/Удалить/ПолучитьЗаписиОВремени.
3. Регистрирует диспетчеризацию в ФасадИнтеграции для нового типа системы.
4. Создаёт элемент справочника «ВнешниеСистемы» с настройками подключения (БазовыйURL, ПараметрыПодключения).
5. Создаёт элементы справочника «ВнешниеЗадачи», связанные с новой внешней системой.

**Постусловие:** Новая внешняя система доступна в таймтрекинге, работник может синхронизировать записи в неё через тот же интерфейс.
