# Описание справочников для подсистемы контроля внешних Issue трекеров

## Контекст

Подсистема обеспечивает интеграцию с внешними трекерами задач (GitLab и аналогичными). Справочники предназначены для хранения маппинга между сущностями 1С и внешними системами, а также данных о тикетах.

---

## 1. ПланВидовХарактеристик.ВнешниеСистемыТикетов

**Назначение:** Учёт внешних систем (GitLab-проекты, Jira-борды и др.), с которыми синхронизируются тикеты.

| № | Наименование реквизита | Тип | Описание |
|---|------------------------|-----|----------|
| 1 | **Ссылка** | ГУИД | Автоматический уникальный идентификатор записи |
| 2 | **Код** | Строка, 50 | Технический код системы (например, "GITLAB", "JIRA") |
| 3 | **Наименование** | Строка, 200 | Отображаемое название системы |
| 4 | **БазовыйURL** | Строка, 255 | URL API внешней системы (например, `https://gitlab.example.com`) |
| 5 | **ТокенДоступа** | Строка, 500 | Токен/ключ аутентификации для доступа к API |
| 6 | **ПроектID** | Строка, 100 | Идентификатор проекта/репозитория во внешней системе |
| 7 | **ПроектПуть** | Строка, 255 | Полный путь к проекту (path_with_namespace) |
| 8 | **Активна** | Булево | Признак активности системы (синхронизация включена/выключена) |
| 9 | **ДатаПоследнейСинхронизации** | Дата | Дата последней успешной синхронизации |
| 10 | **Описание** | Строка, 500 | Описание системы, комментарии |

---

## 2. Справочник.Тикеты

**Назначение:** Хранение данных о тикетах (Issue) из внешних систем. Каждый элемент справочника — один тикет из внешней системы.

| № | Наименование реквизита | Тип | Описание |
|---|------------------------|-----|----------|
| 1 | **Ссылка** | ГУИД | Автоматический уникальный идентификатор записи |
| 2 | **Код** | Строка, 50 | Внутренний код тикета в 1С (автогенерация) |
| 3 | **Наименование** | Строка, 500 | Заголовок/название тикета |
| 4 | **ВнешняяСистема** | СправочникСсылка.ВнешниеСистемыТикетов | Ссылка на внешнюю систему, из которой взят тикет |
| 5 | **ВнешнийИдентификатор** | Строка, 100 | ID/IID тикета во внешней системе (уникальный в рамках системы) |
| 6 | **СсылкаНаВнешнийТикет** | Строка, 255 | URL тикета во внешней системе |
| 7 | **Статус** | Перечисление.СтатусыТикетов | Текущий статус тикета (Открыт, В работе, Закрыт и т.д.) |
| 8 | **Создатель** | Ссылка.ПользователиВнешнихСистем | Автор тикета (пользователь внешней системы) |
| 9 | **Ответственный** | Ссылка.ПользователиВнешнихСистем | Назначенный исполнитель/ответственный |
| 10 | **Приоритет** | Перечисление.ПриоритетыТикетов | Приоритет тикета (Критический, Высокий, Средний, Низкий) |
| 11 | **ДатаСоздания** | Дата | Дата создания тикета во внешней системе |
| 12 | **ДатаОбновления** | Дата | Дата последнего обновления тикета |
| 13 | **ДатаЗакрытия** | Дата | Дата закрытия тикета (если закрыт) |
| 14 | **Описание** | Строка, 5000 | Тело/описание тикета (HTML/Markdown) |
| 15 | **Метка** | Строка, 255 | Метки/теги тикета (через запятую или массив) |
| 16 | **Вид** | Перечисление.ВидыТикетов | Вид тикета: Задача, Инцидент, Фича, Epic и т.д. |
| 17 | **РодительскийТикет** | Ссылка.Тикеты | Ссылка на родительский тикет (для иерархии) |
| 18 | **СвязанныеПроекты** | Справочник.НоменклатурныеГруппы (подбор) | Связанные проекты/номенклатурные группы в 1С |

### Подчинение
- `ВнешняяСистема` → ПланВидовХарактеристик.ВнешниеСистемыТикетов
- `Создатель`, `Ответственный` → Справочник.ПользователиВнешнихСистем
- `РодительскийТикет` → Справочник.Тикеты (самоподчинение)

## 3. Справочник.ПользователиВнешнихСистем

**Назначение:** Хранение пользователей внешних систем для маппинга с сотрудниками 1С и хранения истории тикетов.

| № | Наименование реквизита | Тип | Описание |
|---|------------------------|-----|----------|
| 1 | **Ссылка** | Метаданный | Автоматический уникальный идентификатор записи |
| 2 | **Код** | Строка, 50 | Внутренний код пользователя в 1С (автогенерация) |
| 3 | **Наименование** | Строка, 200 | Полное имя пользователя |
| 4 | **Логин** | Строка, 100 | Логин/username во внешней системе |
| 5 | **ВнешняяСистема** | Ссылка.ВнешниеСистемыТикетов | Внешняя система, в которой зарегистрирован пользователь |
| 6 | **ВнешнийИдентификатор** | Строка, 100 | ID пользователя во внешней системе (уникальный) |
| 7 | **Email** | Строка, 255 | Email пользователя |
| 8 | **Сотрудник1С** | Ссылка.Сотрудники | Связанный сотрудник в 1С (маппинг) |
| 9 | **Активен** | Булево | Признак активности пользователя |
| 10 | **ДатаПоследнейСинхронизации** | Дата | Дата последней синхронизации данных о пользователе |

## 4. Перечисление.СтатусыТикетов

**Назначение:** Статусы тикетов из внешних систем.

| Значение | Описание |
|----------|----------|
| **Открыт** | Тикет открыт, требует внимания |
| **ВРаботе** | Тикет в работе |
| **Ожидание** | Ожидание действий от сторонней стороны |
| **Закрыт** | Тикет закрыт (решён) |
| **Отменён** | Тикет отменён/удалён |

| **Высокий** | Высокий приоритет (P1) |

| Значение | Описание |
|----------|----------|
| **Задача** | Issue / Task (GitLab Issue, Jira Story) |
| **Инцидент** | Bug / Incident (GitLab Bug, Jira Bug) |
| **Фича** | Feature / Enhancement |

| **MergeRequest** | Merge Request / Pull Request |
| **Другое** | Прочее |

## 7. РегистрСведений.МаппингТикетовПроектов1С

**Назначение:** Связывание тикетов внешних систем с проектами/номенклатурными группами 1С.

| № | Наименование реквизита | Тип | Описание |
|---|------------------------|-----|----------|
| **Измерение 1** | **Тикет** | Ссылка.Тикеты | Ссылка на тикет из внешней системы |
| **Измерение 2** | **Проект1С** | Ссылка.Номенклатура | Ссылка на проект/номенклатурную группу в 1С |
| **Ресурс 1** | **ВидРаботы** | Строка, 100 | Тип работы (код вида работ) |
| **Ресурс 2** | **НормативЧасов** | Число, 9.2 | Норматив времени в часах |

---

## 8. РегистрСведений.ТаймшитыВнешнихСистем

**Назначение:** Хранение записей об затраченном времени (timelogs) из внешних систем для расчёта заработной платы по проектам.

| № | Наименование реквизита | Тип | Описание |
|---|------------------------|-----|----------|
| **Измерение 1** | **Тикет** | Ссылка.Тикеты | Тикет, к которому привязана запись времени |
| **Измерение 2** | **Пользователь** | Ссылка.ПользователиВнешнихСистем | Пользователь, выполнивший работу |
| **Измерение 3** | **Период** | Дата | Дата выполнения работы (spent_at) |
| **Ресурс 1** | **ДлительностьВСекундах** | Число, 15.2 | Затраченное время в секундах |
| **Ресурс 2** | **Комментарий** | Строка, 500 | Комментарий к затраченному времени |
| **Ресурс 3** | **ВнешнийИдентификаторЗаписи** | Строка, 100 | ID записи времени во внешней системе (для обновления/удаления) |

## Схема связей между объектами

```
┌──────────────────────────────┐
│  ВнешниеСистемыТикетов       │
│  (план видов характеристик)  │
└────────────┬─────────────────┘
             │
             ├──► Тикеты (справочник)
             │      │
             │      ├──► ПользователиВнешнихСистем (создатель, ответственный)
             │      │
             │      └──► МаппингТикетовПроектов1С (измерение: Тикет)
             │
             └──► ПользователиВнешнихСистем (внешняя система)
                    │
                    └──► Маппинг: Сотрудник1С ←→ ВнешнийИдентификатор

┌──────────────────────────────┐
│  ТаймшитыВнешнихСистем       │
│  (регистр сведений)          │
│                              │
│ Измерения:                   │
│   - Тикет ──► Тикеты         │
│   - Пользователь ───────────►│
│   - Период                   │
└──────────────────────────────┘
```

## Примечания по реализации

1. **ВнешнийИдентификатор** — строковое поле для хранения ID из внешней системы. Это позволяет избежать проблем с типами данных и сохранить совместимость с разными системами.

2. **Связь Сотрудник1С ↔ ПользовательВнешнейСистемы** — устанавливается через реквизит `Сотрудник1С` в справочнике `ПользователиВнешнихСистем`. Это упрощённый подход по сравнению с отдельным планом видов характеристик для маппинга.

3. **ТаймшитыВнешнихСистем** — регистр сведений, который заполняется при синхронизации и используется для расчёта заработной платы по проектам.

4. **МаппингТикетовПроектов1С** — позволяет связать тикеты с конкретными проектами 1С для корректного распределения затрат.
