# Задачи на разработку «ЛистУчетаРабочегоВремени» (TDD)

## Обзор

Документ «ЛистУчетаРабочегоВремени» — ядро подсистемы таймтрекинга. Обеспечивает учёт интервалов рабочего времени работника с автоматической синхронизацией во внешние системы через ФасадИнтеграции.

**Ключевой принцип:** документ не содержит HTTP-вызовов и не знает о конкретных внешних системах. Все операции синхронизации выполняются через `ФасадИнтеграции`.

---

## Задача ЛУР-001: Документ «ЛистУчетаРабочегоВремени» — Создание строки

**Модуль:** `Документ.ЛистУчетаРабочегоВремени.МодульДокумента`  
**Метод:** `СоздатьСтроку(Задача)`  
**Описание:** Создаёт новую строку табличной части с фиксацией времени окончания предыдущей строки.

### Юнит-тесты

#### ТЕСТ-ЛУР-001: Создание первой строки
- **Дано:** Документ «ЛистУчетаРабочегоВремени» создан, состояние = «Черновик», табличная часть пуста
- **Когда:** Вызван `СоздатьСтроку(ЗадачаПоУмолчанию)`
- **То:** Создана строка с Задача=ЗадачаПоУмолчанию, ВремяНачала=ВремяНачалаДня (09:00), ВремяОкончания=ВремяНачалаДня

#### ТЕСТ-ЛУР-002: Создание второй строки фиксирует первую
- **Дано:** Документ содержит одну строку с ВремяНачала="2024-01-15 09:00", ВремяОкончания="2024-01-15 09:00" (не зафиксирована)
- **Когда:** Вызван `СоздатьСтроку(ЗадачаРабочая)` в "2024-01-15 10:30"
- **То:** Первая строка: ВремяОкончания="2024-01-15 10:30"; вторая строка: ВремяНачала="2024-01-15 10:30", Задача=ЗадачаРабочая

#### ТЕСТ-ЛУР-003: Автоматическое определение ТипСтроки
- **Дано:** Вызван `СоздатьСтроку(ЗадачаGitLab)` где ЗадачаGitlab.ВнешняяСистема.ТипСистемы.ИмеетИнтеграцию = Истина
- **Когда:** Строка создана
- **То:** ТипСтроки = «Рабочая» (синхронизируется)

#### ТЕСТ-ЛУР-004: Автоматическое определение ТипСтроки для обеда
- **Дано:** Вызван `СоздатьСтроку(ЗадачаОбед)` где ЗадачаОбед.ВнешняяСистема.ТипСистемы.ИмеетИнтеграцию = Ложь
- **Когда:** Строка создана
- **То:** ТипСтроки = «Не синхронизируется»

#### ТЕСТ-ЛУР-005: ВремяНачала новой строки = ВремяОкончания предыдущей
- **Дано:** Документ содержит строку с ВремяОкончания="2024-01-15 14:00"
- **Когда:** Вызван `СоздатьСтроку(ЗадачаНовая)`
- **То:** Новая строка получает ВремяНачала="2024-01-15 14:00"

## Задача ЛУР-002: Документ «ЛистУчетаРабочегоВремени» — Автопродление последней строки

**Модуль:** `Документ.ЛистУчетаРабочегоВремени.МодульДокумента`  
**Метод:** `АвтопродлитьПоследнююСтроку()`  
**Описание:** Обновляет ВремяОкончания последней активной строки на текущую дату и время.

### Юнит-тесты

#### ТЕСТ-ЛУР-006: Автопродление последней строки
- **Дано:** Документ в состоянии «Активен», последняя строка с ВремяНачала="2024-01-15 09:00", ВремяОкончания="2024-01-15 09:00"
- **Когда:** Вызван `АвтопродлитьПоследнююСтроку()` в "2024-01-15 09:07" (через 7 минут)
- **То:** ВремяОкончания последней строки = "2024-01-15 09:07"

#### ТЕСТ-ЛУР-007: Автопродление не работает в состоянии «Завершён»
- **Дано:** Документ в состоянии «Завершён», последняя строка с ВремяОкончания="2024-01-15 18:00"
- **Когда:** Вызван `АвтопродлитьПоследнююСтроку()` в "2024-01-15 18:07"
- **То:** ВремяОкончания не изменилось ("2024-01-15 18:00")

#### ТЕСТ-ЛУР-008: Автопродление игнорирует пустой документ
- **Дано:** Документ в состоянии «Активен», табличная часть пуста (нет строк)
- **Когда:** Вызван `АвтопродлитьПоследнююСтроку()`
- **То:** Исключение не генерируется, документ остаётся без изменений

## Задача ЛУР-004: Документ «ЛистУчетаРабочегоВремени» — Группировка строк для синхронизации

#### ТЕСТ-ЛУР-012: Группировка последовательных строк с одной задачей
- **Дано:** Документ содержит 3 последовательные строки с Задача=ЗадачаА, суммарная длительность = 7200 секунд
- **Когда:** Вызван `СгруппироватьСтрокиДляСинхронизации()`
- **То:** Возвращается массив из одной группы: Задача=ЗадачаА, Длительность=7200, Комментарий=""

#### ТЕСТ-ЛУР-013: Разделение групп при смене задачи
- **Дано:** Документ содержит строки: [ЗадачаА(1800с), ЗадачаБ(900с), ЗадачаА(600с)]
- **Когда:** Вызван `СгруппироватьСтрокиДляСинхронизации()`
- **То:** Возвращается массив из 3 групп: [ЗадачаА,1800], [ЗадачаБ,900], [ЗадачаА,600]

#### ТЕСТ-ЛУР-014: Объединение комментариев в группе

- **Когда:** Вызван `СгруппироватьСтрокиДляСинхронизации()`
- **То:** ИтоговыйКомментарий группы = "Работа над модулем; Исправление багов"

#### ТЕСТ-ЛУР-015: Уникализация комментариев
- **Дано:** Документ содержит группу строк с повторяющимися комментариями ["Тест", "Тест", "Отладка"]
- **Когда:** Вызван `СгруппироватьСтрокиДляСинхронизации()`
- **То:** ИтоговыйКомментарий группы = "Тест; Отладка" (уникальные через "; ")

#### ТЕСТ-ЛУР-016: Пустая группа при пустом документе

## Задача ЛУР-005: Документ «ЛистУчетаРабочегоВремени» — Синхронизация с Фасадом (основной поток)

**Модуль:** `Документ.ЛистУчетаРабочегоВремени.МодульДокумента`  
**Метод:** `Синхронизировать()`  
**Описание:** Выполняет синхронизацию строк документа со внешними системами через ФасадИнтеграции.

### Юнит-тесты

#### ТЕСТ-ЛУР-017: Синхронизация группы с пустым ID
- **Дано:** Группа из `СгруппироватьСтрокиДляСинхронизации()`: Задача=ЗадачаGitLab, Длительность=3600, Комментарий="Работа", ИдентификаторЗаписиВремени="" (пустой)
- **Когда:** Вызван `Синхронизировать()`
- **То:** Вызван `ФасадИнтеграции.ДобавитьЗаписьОВремени(ЗадачаGitLab, 3600, ДатаРаботы, "Работа")`, новый ID записан во все строки группы

#### ТЕСТ-ЛУР-018: Пропуск синхронизации при актуальном ID
- **Дано:** Группа с ИдентификаторЗаписиВремени="500" (заполнен, данные не менялись)
- **Когда:** Вызван `Синхронизировать()`
- **То:** ФасадИнтеграции не вызывается, группа пропущена

#### ТЕСТ-ЛУР-019: Пересинхронизация при изменении данных
- **Дано:** Группа с ИдентификаторЗаписиВремени="500", но комментарий в строках изменён на "Новый комментарий"
- **Когда:** Вызван `Синхронизировать()`
- **То:** Вызван `ФасадИнтеграции.УдалитьЗаписьОВремени("500")`, затем `ФасадИнтеграции.ДобавитьЗаписьОВремени(...)`, новый ID записан

#### ТЕСТ-ЛУР-020: Синхронизация нескольких групп
- **Дано:** 2 группы для синхронизации, обе с пустыми ID
- **Когда:** Вызван `Синхронизировать()`
- **То:** Для каждой группы вызваны соответствующие методы фасада, все строки получили новые ID

#### ТЕСТ-ЛУР-021: Пропуск групп без интеграции
- **Дано:** Группа с ЗадачаОбед (ИмеетИнтеграцию = Ложь)
- **Когда:** Вызван `Синхронизировать()`
- **То:** ФасадИнтеграции не вызывается, группа пропущена

## Задача ЛУР-011: Форма документа — Перемещение строки вверх/вниз

**Модуль:** `Форма.ЛистУчетаРабочегоВремени`  
**Команда:** `СтрокаВверх` (и аналогично `СтрокаВниз`)  
**Описание:** Меняет местами текущую строку с предыдущей (или следующей), сохраняя длительность каждой. ВремяНачала и ВремяОкончания обновляются согласно новому порядку строк.

### Юнит-тесты формы

#### ТЕСТ-ЛУР-038: Перемещение второй строки вверх
- **Дано:** Документ содержит 2 строки: Строка1 с ВремяНачала="2024-01-15 09:00", ВремяОкончания="2024-01-15 10:00"; Строка2 (текущая) с ВремяНачала="2024-01-15 10:00", ВремяОкончания="2024-01-15 10:00", Задача=ЗадачаБ
- **Когда:** Выбрана Строка2, выполнена команда `СтрокаВверх`
- **То:** Строки поменялись местами: Строка1 (ЗадачаБ) с ВремяНачала="2024-01-15 09:00", ВремяОкончания="2024-01-15 09:00"; Строка2 (ЗадачаА) с ВремяНачала="2024-01-15 09:00", ВремяОкончания="2024-01-15 10:00"

#### ТЕСТ-ЛУР-039: Перемещение первой строки вверх — отказ
- **Дано:** Выбрана первая (единственная в группе) строка
- **Когда:** Выполнена команда `СтрокаВверх`
- **То:** Строка не перемещена, выводится сообщение "Нельзя переместить выше"

#### ТЕСТ-ЛУР-040: Перемещение с сохранением ИдентификаторЗаписиВремени
- **Дано:** Строка2 с ИдентификаторЗаписиВремени="500" перемещена вверх
- **Когда:** Выполнена команда `СтрокаВверх`
- **То:** ИдентификаторЗаписиВремени="500" остался у той же логической строки (с ЗадачейБ), несмотря на смену порядка в таблице

#### ТЕСТ-ЛУР-041: Перемещение меняет индикаторы строк
- **Дано:** После перемещения строки жёлтый и зелёный индикаторы
- **Когда:** Выполнена команда `СтрокаВверх`
- **То:** Индикаторы привязаны к логическим строкам (по задаче и данным), а не к позициям в таблице — жёлтая строка остаётся жёлтой на новой позиции

## Задача ЛУР-012: Форма документа — Запоминание прошлых значений при изменении строки

**Модуль:** `Форма.ЛистУчетаРабочегоВремени`  
**Описание:** При изменении реквизита строки (комментарий, задача) форма запоминает предыдущее значение для определения необходимости синхронизации и поддержки отмены изменений (Ctrl+Z).

### Юнит-тесты формы

#### ТЕСТ-ЛУР-042: Запоминание значения комментария при изменении
- **Дано:** Строка с ИдентификаторЗаписиВремени="500", Комментарий="Старый"
- **Когда:** Пользователь изменил комментарий на "Новый" в элементе таблицы
- **То:** Запомнено прошлое значение = "Старый", строка получила жёлтый индикатор

#### ТЕСТ-ЛУР-043: Отмена изменения (Ctrl+Z) восстанавливает прошлое значение
- **Дано:** Строка с запомненным прошлым значением комментария = "Старый"
- **Когда:** Выполнена отмена изменений
- **То:** Комментарий восстановлен в "Старый", жёлтый индикатор снят

#### ТЕСТ-ЛУР-044: Запоминание значения задачи при изменении
- **Дано:** Строка с ИдентификаторЗаписиВремени="500", Задача=ЗадачаА
- **Когда:** Пользователь изменил задачу на ЗадачаБ
- **То:** Запомнено прошлое значение = ЗадачаА, строка получила жёлтый индикатор, требуется пересинхронизация

#### ТЕСТ-ЛУР-045: Изменение не синхронизируемой строки не требует ID
- **Дано:** Строка с ЗадачаОбед (ИмеетИнтеграцию = Ложь), пользователь изменил комментарий
- **Когда:** Комментарий изменён
- **То:** Прошлое значение запомнено, жёлтый индикатор НЕ устанавливается (синхронизация не нужна)

## Задача ЛУР-013: Форма документа — Команда "Собрать таймлоги на дату"

**Модуль:** `Форма.ЛистУчетаРабочегоВремени`  
**Команда:** `СобратьТаймлогиНаДату`  
**Описание:** Получает все таймлоги пользователя на выбранную дату из всех не архивных систем учета, проводит синхронизацию и формирует строки документа.

### Юнит-тесты формы

#### ТЕСТ-ЛУР-046: Сбор таймлогов из одной системы
- **Дано:** Документ на "2024-01-15" пуст, ФасадИнтеграции.ПолучитьЗаписиОВремениЗаПериод возвращает 2 записи GitLab: [09:00-12:00 "Модуль", 13:00-17:00 "Отладка"]
- **Когда:** Выполнена команда `СобратьТаймлогиНаДату`
- **То:** Созданы 2 строки: Строка1 (Задача=ЗадачаGitLabМодуль, ВремяНачала=09:00, ВремяОкончания=12:00), Строка2 (Задача=ЗадачаGitLabОтладка, ВремяНачала=13:00, ВремяОкончания=17:00), все получили ИдентификаторЗаписиВремени

#### ТЕСТ-ЛУР-047: Синхронизация по ИД таймлога
- **Дано:** В документе есть строка с ИдентификаторЗаписиВремени="500", во внешней системе эта запись изменилась (другой комментарий)
- **Когда:** Выполнена команда `СобратьТаймлогиНаДату`
- **То:** Вызван Фасад для проверки по конкретному ИД, строка обновлена, жёлтый индикатор если данные расходятся

#### ТЕСТ-ЛУР-048: Добавление новых записей в конец нарастающим итогом
- **Дано:** В документе есть одна строка 09:00-10:00 (не синхронизирована), Фасад вернул записи [09:00-12:00, 13:00-17:00]
- **Когда:** Выполнена команда `СобратьТаймлогиНаДату`
- **То:** Первая строка скорректирована до 09:00-10:00 (длительность сохранена), добавлена Строка2 (10:00-12:00), Строка3 (13:00-17:00)

#### ТЕСТ-ЛУР-049: Обработка систем со статусом "серый" (не достучались)
- **Дано:** Фасад вернул записи: GitLab — успешно, Jira — ошибка подключения
- **Когда:** Выполнена команда `СобратьТаймлогиНаДату`
- **То:** Записи из GitLab добавлены с зелёным индикатором, из Jira — с серым (не синхронизированы), ИдентификаторЗаписиВремени для Jira = пустой

#### ТЕСТ-ЛУР-050: Повторный сбор обновляет существующие строки
- **Дано:** В документе есть 3 строки с ИдентификаторыЗаписейВремени, Фасад вернул те же ID но с изменёнными данными для одной записи
- **Когда:** Выполнена команда `СобратьТаймлогиНаДату`
- **То:** Строка с изменившимися данными обновлена и получила жёлтый индикатор, остальные — зелёный

## Задача ЛУР-014: Форма документа — Обработчики изменения элементов таблицы отчёта

**Модуль:** `Форма.ЛистУчетаРабочегоВремени`  
**Элемент:** Таблица "ОтчетЗаДень"  
**Описание:** Обработчики событий изменения таблицы обеспечивают корректное обновление времён всех строк при изменении любой ячейки ВремяНачала или ВремяОкончания.

### Юнит-тесты формы

#### ТЕСТ-ЛУР-051: Изменение ВремяНачала строки сдвигает следующую
- **Дано:** 3 строки: [09:00-10:00, 10:00-12:00, 12:00-17:00], пользователь изменил ВремяНачала Строки2 на "2024-01-15 11:00"
- **Когда:** Сработал обработчик `ОтчетЗаДеньНачалоПриИзменении`
- **То:** Строка1: ВремяОкончания="2024-01-15 10:59:59" (за секунду до начала следующей), Строка2: ВремяНачала="11:00", Строка3: ВремяНачала сдвинута на "2024-01-15 12:00" → "2024-01-15 13:00"

#### ТЕСТ-ЛУР-052: Изменение ВремяОкончания текущей строки
- **Дано:** Строка с ВремяНачала="09:00", ВремяОкончания="09:00" (автопродление), пользователь изменил ВремяОкончания на "10:30"
- **Когда:** Сработал обработчик `ОтчетЗаДеньПриИзменении`
- **То:** Длительность строки = 1 час 30 мин, если есть следующая строка — её ВремяНачала сдвинута

#### ТЕСТ-ЛУР-053: Удаление строки пересчитывает таблицу
- **Дано:** 3 строки [09:00-10:00, 10:00-12:00, 12:00-17:00], удалена Строка2
- **Когда:** Сработал обработчик `ОтчетЗаДеньПослеУдаления`
- **То:** Строка1: ВремяОкончания="2024-01-15 09:59:59" (за секунду до Строки3), Строка3: ВремяНачала="10:00", ВремяОкончания="17:00"

#### ТЕСТ-ЛУР-054: Запоминание прошлых значений перед изменением
- **Дано:** Пользователь начал изменение ВремяНачала строки
- **Когда:** Сработал обработчик `ОтчетЗаДеньПередНачаломИзменения`
- **То:** Запомнены исходные значения ВремяНачала и ВремяОкончания текущей строки для поддержки отмены
