# Задачи на разработку ФасадаИнтеграции (TDD)

## Архитектурная модель

### Иерархия контекстов обработки

```
┌──────────────────────────────────────────────────────────────┐
│  Обработка «ФасадИнтеграции» — КОНТЕКСТ СЕССИИ ФАСАДА        │
│  (один пользователь, одна сессия, все задачи документа)      │
│                                                              │
│  Контекст: ИдентификаторПользователя, ДатаСинхронизации     │
│                                                              │
│  ┌──────────────────────────────────────────────────────┐   │
│  │ Обработка «ПодключениеGitLab» — КОНТЕКСТ ПОДКЛЮЧЕНИЯ  │   │
│  │ (контекст обработки подключения фасада к внешней сист.)│   │
│  │                                                        │   │
│  │ Контекст: БазовыйURL, ТокенАутентификации             │   │
│  │                                                        │   │
│  │  ┌──────────────────────────────────────────────┐    │   │
│  │  │ Обработка «ИнтеграцияGitLab» — КОНТЕКСТ ИНТ.  │    │   │
│  │  │ (контекст обработок интеграции с внешней сист.)│    │   │
│  │  │                                               │    │   │
│  │  │ Контекст: ДанныеПодключения, ТокенАвторизации  │    │   │
│  │  │                                               │    │   │
│  │  │  ┌──────────────────────────────────────┐    │    │   │
│  │  │  │ HTTPКоннектор                        │    │    │   │
│  │  │  │ - ВыполнитьGET()                     │    │    │   │
│  │  │  │ - ВыполнитьPOST()                    │    │    │   │
│  │  │  │ - ВыполнитьDELETE()                  │    │    │   │
│  │  │  └──────────────────────────────────────┘    │    │   │
│  │  └──────────────────────────────────────────────┘    │   │
│  └──────────────────────────────────────────────────────┘   │
└──────────────────────────────────────────────────────────────┘
```

### Жизненный цикл

1. **Создание ФасадаИнтеграции** — создаётся обработка сессии фасада для одного пользователя
2. **Первый вызов метода фасада** (например ДобавитьЗаписьОВремени) — фасад определяет ТипВнешнейСистемы по Задача.ВнешняяСистема.ТипСистемы
3. **Проверка кэша подключений** — если обработка подключения для данного типа системы уже создана в контексте сессии — используется существующая
4. **Создание обработки подключения** — если не найдена, фасад создаёт обработку «Подключение{ТипСистемы}» (контекст подключения)
5. **Создание обработки интеграции** — обработка подключения порождает обработку «Интеграция{ТипСистемы}» (контекст интеграции) с данными подключения и авторизации
6. **Вызов метода интеграции** — фасад делегирует вызов обработке интеграции
7. **Завершение сессии фасада** — все обработки подключения и интеграции уничтожаются

## Задача FAS-001: ФасадИнтеграции — Создание сессии

**Модуль:** `Обработка.ФасадИнтеграции`  
**Описание:** Создаёт сессию фасада для одного пользователя. Одна сессия обрабатывает все задачи документа синхронизации.

### Юнит-тесты

#### ТЕСТ-FAS-001: Создание сессии фасада
- **Дано:** Новая обработка «ФасадИнтеграции» не инициализирована
- **Когда:** Вызван `ИнициализироватьСессию(ИдентификаторПользователя)`
- **То:** Сессия создана, ИдентификаторПользователя сохранён в контексте сессии

#### ТЕСТ-FAS-002: Повторная инициализация той же сессии
- **Дано:** Сессия фасада уже инициализирована для пользователя 42
- **Когда:** Вызван `ИнициализироватьСессию(42)` повторно
- **То:** Возвращается Истина, контекст не сбрасывается

#### ТЕСТ-FAS-003: Инициализация сессии для другого пользователя
- **Дано:** Сессия фасада инициализирована для пользователя 42
- **Когда:** Вызван `ИнициализироватьСессию(99)` (другой пользователь)
- **То:** Старая сессия завершается, создаётся новая сессия для пользователя 99

#### ТЕСТ-FAS-004: Получение идентификатора пользователя из сессии
- **Дано:** Сессия инициализирована с ИдентификаторПользователя=42
- **Когда:** Вызван `ПолучитьИдентификаторПользователя()`
- **То:** Возвращается 42

#### ТЕСТ-FAS-005: Получение идентификатора пользователя до инициализации
- **Дано:** Сессия не инициализирована
- **Когда:** Вызван `ПолучитьИдентификаторПользователя()`
- **То:** Генерируется исключение «Сессия фасада не инициализирована»

## Задача FAS-002: ФасадИнтеграции — Диспетчеризация по типу системы

**Модуль:** `Обработка.ФасадИнтеграции`  
**Методы:** `ДобавитьЗаписьОВремени()`, `ИзменитьЗаписьОВремени()`, `УдалитьЗаписьОВремени()`  
**Описание:** Определяет тип внешней системы по Задача и делегирует вызов соответствующей обработке интеграции.

### Юнит-тесты

#### ТЕСТ-FAS-006: Диспетчеризация для GitLab
- **Дано:** Сессия инициализирована, Задача имеет ВнешняяСистема.ТипСистемы = GitLab
- **Когда:** Вызван `ДобавитьЗаписьОВремени(ЗадачаGitLab, 3600, "2024-01-15", "Описание")`
- **То:** Создана обработка подключения «ПодключениеGitLab» (если не создана), порождена обработка интеграции «ИнтеграцияGitLab», вызван её метод `ДобавитьЗаписьОВремени()`

#### ТЕСТ-FAS-007: Диспетчеризация для Jira
- **Дано:** Сессия инициализирована, Задача имеет ВнешняяСистема.ТипСистемы = Jira
- **Когда:** Вызван `ДобавитьЗаписьОВремени(ЗадачаJira, 3600, "2024-01-15", "Описание")`
- **То:** Создана обработка подключения «ПодключениеJira», порождена обработка интеграции «ИнтеграцияJira», вызван её метод `ДобавитьЗаписьОВремени()`

#### ТЕСТ-FAS-008: Кэширование обработки подключения в сессии
- **Дано:** Вызван `ДобавитьЗаписьОВремени(ЗадачаGitLab, ...)` первый раз — создана обработка «ПодключениеGitLab»
- **Когда:** Вызван `УдалитьЗаписьОВремени(ID)` для той же задачи GitLab во второй раз
- **То:** Используется существующая обработка подключения «ПодключениеGitLab», новая не создаётся

#### ТЕСТ-FAS-009: Обработка задачи без интеграции
- **Дано:** Сессия инициализирована, Задача имеет ВнешняяСистема.ТипСистемы = Внутренняя (ИмеетИнтеграцию = Ложь)
- **Когда:** Вызван `ДобавитьЗаписьОВремени(ЗадачаВнутренняя, 3600, "2024-01-15", "Описание")`
- **То:** Возвращается пустая строка (ID записи не генерируется), интеграция не вызывается

#### ТЕСТ-FAS-010: Обработка неизвестного типа системы
- **Дано:** Сессия инициализирована, Задача имеет неизвестный тип системы
- **Когда:** Вызван `ДобавитьЗаписьОВремени(ЗадачаНеизвестная, 3600, "2024-01-15", "Описание")`
- **То:** Генерируется исключение «Неизвестный тип внешней системы: {Наименование}»

## Задача FAS-003: ФасадИнтеграции — ПолучитьСписокЗадач

**Модуль:** `Обработка.ФасадИнтеграции`  
**Метод:** `ПолучитьСписокЗадач(ТипВнешнейСистемы, ИдентификаторПользователя)` → ТаблицаЗначений  
**Описание:** Запрашивает задачи у соответствующей обработки интеграции и объединяет результаты.

### Юнит-тесты

#### ТЕСТ-FAS-011: Получение задач GitLab
- **Дано:** Сессия инициализирована, обработка подключения «ПодключениеGitLab» создана
- **Когда:** Вызван `ПолучитьСписокЗадач(ТипВнешнейСистемы.GitLab, 42)`
- **То:** Обработка интеграции «ИнтеграцияGitLab.ПолучитьЗадачи(42)» возвращает ТаблицуЗначений с задачами

#### ТЕСТ-FAS-012: Объединение задач из нескольких систем
- **Дано:** Сессия инициализирована, созданы обработки подключения для GitLab и Jira
- **Когда:** Вызван `ПолучитьСписокЗадач(ТипВнешнейСистемы.Все, 42)` (тип «Все» = объединить все системы)
- **То:** Возвращается объединённая ТаблицаЗначений с задачами из GitLab и Jira

#### ТЕСТ-FAS-013: Пустой список задач при отсутствии интеграции
- **Дано:** Сессия инициализирована, но обработка подключения «ПодключениеGitLab» не создана (нет настроек)
- **Когда:** Вызван `ПолучитьСписокЗадач(ТипВнешнейСистемы.GitLab, 42)`
- **То:** Возвращается пустая ТаблицаЗначений

## Задача FAS-009: Обработка «ИнтеграцияGitLab» — ДобавитьЗаписьОВремени

**Модуль:** `Обработка.ИнтеграцияGitLab`  
**Метод:** `ДобавитьЗаписьОВремени(ВнешняяЗадача, ДлительностьВСекундах, ДатаРаботы, Описание)` → ИдентификаторЗаписиВремени

### Юнит-тесты

#### ТЕСТ-FAS-029: Добавление timelog в GitLab
- **Дано:** Обработка «ИнтеграцияGitLab» инициализирована, mock HTTP возвращает JSON с timelog_id=500 со статусом 201
- **Когда:** Вызван `ДобавитьЗаписьОВремени(ВнешняяЗадача, 3600, "2024-01-15", "Описание")`
- **То:** Возвращается "500" (timelog_id из ответа)

#### ТЕСТ-FAS-030: Формирование URL для POST timelogs
- **Дано:** Обработка «ИнтеграцияGitLab» инициализирована с БазовыйURL="https://gitlab.example.com", ВнешняяЗадача имеет ВнешнийИдентификатор="group/proj:42"
- **Когда:** Вызван `ДобавитьЗаписьОВремени(ВнешняяЗадача, 3600, "2024-01-15", "Описание")`
- **То:** POST отправлен на URL "https://gitlab.example.com/api/v4/projects/group%2Fproj/issues/42/time_spent"

#### ТЕСТ-FAS-031: Формирование тела запроса timelog
- **Дано:** Обработка «ИнтеграцияGitLab» инициализирована, mock HTTP возвращает JSON со статусом 201
- **Когда:** Вызван `ДобавитьЗаписьОВремени(ВнешняяЗадача, 3600, "2024-01-15", "Описание")`
- **То:** Тело запроса содержит {"duration": "1h", "spent_at": "2024-01-15T00:00:00Z", "summary": "Описание"}

#### ТЕСТ-FAS-032: Обработка ошибки 401 при добавлении timelog
- **Дано:** Обработка «ИнтеграцияGitLab» инициализирована, mock HTTP возвращает 401 со статусом 401
- **Когда:** Вызван `ДобавитьЗаписьОВремени(ВнешняяЗадача, 3600, "2024-01-15", "Описание")`
- **То:** Генерируется исключение «Ошибка аутентификации GitLab: 401 Unauthorized»

#### ТЕСТ-FAS-033: Обработка ошибки 404 при добавлении timelog
- **Дано:** Обработка «ИнтеграцияGitLab» инициализирована, mock HTTP возвращает 404 со статусом 404
- **Когда:** Вызван `ДобавитьЗаписьОВремени(ВнешняяЗадача, 3600, "2024-01-15", "Описание")`
