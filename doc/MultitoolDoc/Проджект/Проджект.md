# Проджект — планирование проектов (подсистема Project)

Статус: в разработке (этап 1 — модель данных).
Цель: повторить в 1С функциональность MS Project, необходимую для планирования работ,
с возможностью импорта проектов из MS Project.

## 1. Границы функциональности

### Берём из MS Project
| Возможность | Комментарий |
|---|---|
| Задачи (работы) с иерархией | сводные задачи, уровни структуры, WBS |
| Связи задач **только тип «Конец–Начало» (FS)** | с опережением/запаздыванием (lag/lead); прочие типы (SS, FF, SF) не поддерживаются |
| Ресурсы | трудовые, материальные, затратные |
| Календари | базовые календари, календари ресурсов, календарь проекта, исключения (праздники/отпуска) |
| Выравнивание перегрузок ресурсов | как в MS Project Pro: сдвиг и **разбиение задач на куски** (splits) |
| Базовые планы | версии расписания (снимки Start/Finish/Duration/Work/Cost) |
| Обмен | импорт/экспорт MSPDI XML (`*.xml` из «Сохранить как» MS Project) |

### Не берём (осознанно)
- Связи SS / FF / SF, внешние связи между проектами (cross-project links — реквизиты хранятся, но не рассчитываются).
- Сетевые графики/отчёты MS Project, портфели, серверная часть (Project Server).
- Проценты выполнения в деталях повремёнки — фактический учёт времени остаётся в подсистеме Таймтрекинг (интеграция отложена).
- Рекуррентные (ежегодные и т.п.) исключения календарей — только исключения с диапазоном дат.
- Ручное планирование (manually scheduled) — реквизит хранится, но расчёт пока всегда автоматический.

Методологическая привязка (FPF): границы и связка «использование ↔ концепция» — SYSE.2
(Develop Linked Use and System Concepts); выбор способа получения результата (реализуем сами
движок расписания, календари берём собственные, форматы обмена — по схеме MSPDI) — SYSE.24;
декомпозиция на следующие шаги реализации — SYSE.3.

## 2. Сценарии использования

1. **Импорт проекта**: пользователь сохраняет план из MS Project в XML и загружает его —
   получаются Проект, Работы (иерархией), Ресурсы, Календари, связи FS, назначения.
2. **Расчёт расписания**: по нажатию кнопки (или при записи) система пересчитывает
   Start/Finish работ по календарям и связям FS, считает резервы и критический путь.
3. **Выравнивание**: система находит перегрузки ресурсов (сумма Units×работ по дням > MaxUnits)
   и устраняет их сдвигом задач и разбиением на куски (в пределах slack, если включено).
4. **Сверка с базовым планом**: сохранение версии расписания и сравнение текущих дат/длительностей
   с сохранёнными.
5. **Экспорт в MS Project**: выгрузка текущего расписания в MSPDI XML (обратная совместимость).

## 3. Модель данных

Имена реквизитов повторяют имена полей **MSPDI XML** (формат обмена MS Project), чтобы
импорт/экспорт был прямым отображением. Единицы хранения: длительность и работа — **минуты**;
Units — **проценты** (в MSPDI — доля 1.0 = 100%, при импорте ×100).

## 4. Алгоритмы

### 4.1 Календарная математика
- Календарь ресурса/задачи наследует базовый календарь (BaseCalendar), переопределяя дни.
- День недели + WeekDays (день рабочий, 1–3 интервала) + Exceptions (диапазон дат).
- Базовые операции: `РабочиеИнтервалыДня(календарь, дата)`, `ЕстьРабочееВремя(дата, календарь)`,
  `СледующийРабочийМомент(момент, календарь)`, `ДобавитьРабочееВремя(момент, минуты, календарь)`,
  `РабочихМинутМежду(начало, конец, календарь)`.
- Elapsed-длительности (коды 4/6/8/10/12) считаются по астрономическому времени, минуя календарь.

### 4.2 Прямой проход (CPM)
Для каждой работы в топологическом порядке (по OutlineLevel/ID):
- ES = max(по предшественникам FS: EF предшественника + Lag в рабочем времени календаря преемника;
  по ограничениям SNET/FNET/MSO: ConstraintDate; для ALAP/FNLT/MFO — обратный проход),
  приведённый к следующему рабочему моменту календаря задачи (+LevelingDelay).
- EF = ES + Duration рабочими минутами (fixed duration — по календарю задачи).
- Сводная: Start = min детей, Finish = max детей, Duration = рабочие минуты между ними.

### 4.3 Обратный проход
- LF проекта = max Finish; для работ без преемников LF = LF проекта (учёт Deadline — при желании).
- LS = LF − Duration; резерв TotalSlack = LS − ES (рабочие минуты); FreeSlack = min(ES преемников) − EF.
- Critical = TotalSlack ≤ 0. Ограничения SNLT/FNLT/MFO/ALAP учитываются на обратном проходе.

### 4.4 Длительность / работа / назначения
Формулы MS Project (для трудовых ресурсов):
- Work(минуты) = Σ по назначениям (Duration × Units/100) для Fixed Units;
- Fixed Duration: изменение Work пересчитывает Units; Fixed Work: изменение Units пересчитывает Duration;
- EffortDriven: добавление ресурса не увеличивает суммарную Work;
- материальные ресурсы не имеют длительности/работы — только количество (Units) и стоимость;
- Cost = FixedCost + Σ (Work/60 × StandardRate + CostPerUse) + прочее.

### 4.5 Выравнивание с разбиением (как в MS Project Pro)
1. Находим перегрузки: для каждого дня (и интервала календаря ресурса) сумма
   Units назначений (учитывая LevelingDelay и Delay) > MaxUnits ресурса.
2. Порядок задач — LevelingOrder проекта (по умолчанию: приоритет, затем стандартный порядок ID).
   Priority = 1000 — не выравнивать. Материальные и затратные ресурсы не выравниваются.
3. Устранение перегрузки: сдвиг задачи (LevelingDelay) на свободные куски ресурса;
   если разрешено разбиение (LevelingCanSplit проекта и задачи) и дальше сдвигать нельзя
   (или включено «в пределах slack»), работа разбивается: незанятые периоды ресурса
   пропускаются, создаются сегменты в справочнике ИнтервалыРабот.
4. Опционально — не выходить за пределы TotalSlack («level within slack»).
5. После выравнивания — пересчёт расписания (4.2–4.3).

### 4.6 Импорт/экспорт MSPDI
- Читается XML по схеме mspdi.xsd (namespace `http://schemas.microsoft.com/project`).
- Связка объектов по UID (строка 36). Длительности в десятых долях минуты конвертируются.
- Ссылки PredecessorLink собираются после загрузки всех задач (двухфазная загрузка).
- Не поддерживаемое (типы связей ≠ FS, recurring-исключения, подпроекты) — пропускается
  с записью в журнал предупреждений.

## 5. Архитектура
Подсистема **Project** самодостаточна: не использует справочники других подсистем.
```
Catalogs: Проект, Работы, Ресурсы, ГрафикиРаботы, ИнтервалыРабот, ВерсияРасписанияПроекта
Common modules (план):
  КалендариПроектов      — календарная математика (4.1)
  ПланированиеПроектов   — расчёт расписания CPM (4.2–4.3), сводный пересчёт (4.4)
  ВыравниваниеРесурсов   — выравнивание с разбиением (4.5)
  ОбменMSProject         — импорт/экспорт MSPDI (4.6)
```
Правила кодирования — по AGENTS.md: декомпозиция на малые функции, top-down,
гексагональное разделение (движок расчёта не знает о формах и обмене; обмен — адаптер к XML).

## 6. Справочник кодов MSPDI

### 6.1 Тип связи (Link.Type)
FF=0, FS=1, SF=2, SS=3 (поддерживается только FS=1).

### 6.2 Ограничение (Task.ConstraintType)
0=ASAP, 1=ALAP, 2=SNET, 3=SNLT, 4=FNET, 5=FNLT, 6=MSO, 7=MFO.

### 6.3 Тип задачи (Task.Type) / ресурса (Resource.Type)
Task: 0=Fixed Units, 1=Fixed Duration, 2=Fixed Work.
Resource: 0=Material, 1=Work, 2=Cost.

### 6.4 Формат длительности (DurationFormat/LagFormat)
3=m, 4=em (elapsed m), 5=h, 6=eh, 7=d, 8=ed, 9=w, 10=ew, 11=mo, 12=emo,
19=%, 20=e%, 21=null. Коды оценочных длительностей (35+) уточняются при реализации импорта.

### 6.5 Дни недели (WeekDay.DayType)
MSPDI: 1=Sunday … 7=Saturday. Храним в 1С как 1=Понедельник … 7=Воскресенье:
`день1С = ((деньMSPDI − 2 + 7) mod 7) + 1`.

### 6.6 Начисление затрат (AccrueAt)
1=Start, 2=Prorated, 3=End.
