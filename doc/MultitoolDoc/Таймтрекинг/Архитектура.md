# Архитектура подсистемы Таймтрекинг

## 1. Общая концепция

Система оперативного, но корректируемого учёта рабочего времени работника. Главный заказчик — работник, поэтому удобство ввода приоритетно. Аналитические отчёты смотрят другие люди.

**Ключевая идея:** «Редактируемый лист дня» — таблица интервалов работы, а не старт/стоп по задачам.

## 2. Модель данных

### 2.1 Справочники

#### Справочник «ТипыВнешнихСистем»
- **Наименование** — GitLab, Jira, Внутренняя и т.п.
- **ИмеетИнтеграцию** (Булево) — определяет, нужно ли синхронизировать задачи этого типа с внешним API. Для обедов и локальных задач = Ложь.

#### Справочник «ВнешниеСистемы»
- **Наименование** — «GitLab Компании», «Jira Проект X».
- **ТипСистемы** — ссылка на «ТипыВнешнихСистем».
- **БазовыйURL** — корень API.
- **ПараметрыПодключения** (ХранилищеЗначения) — JSON с общими настройками аутентификации.

#### Справочник «ВнешниеЗадачи»
- **Наименование** — краткое описание задачи.
- **ВнешняяСистема** — ссылка на «ВнешниеСистемы». Определяет, куда синхронизировать.
- **ВнешнийИдентификатор** (строка) — ID задачи в формате API (например, group/proj:42).
- **Активна** (Булево).
- **СсылкаНаВеб** — URL для открытия в браузере.

Для обеда создаётся:
- Элемент «Внутренняя» в «ТипыВнешнихСистем» (ИмеетИнтеграцию = Ложь)
- Элемент «Локальные задачи» в «ВнешниеСистемы» (тип = Внутренняя)
- Элемент «Обед» в «ВнешниеЗадачи» (ВнешняяСистема = Локальные задачи, ВнешнийИдентификатор пустой)

### 2.2 Документ «ЛистУчетаРабочегоВремени»

#### Реквизиты шапки
- **Дата** — дата, на которую составляется лист.
- **ВремяНачалаДня** (Дата/Время) — точка отсчёта, по умолчанию 09:00.
- **ВремяОкончанияДня** (Дата/Время) — завершающая граница.
- **Автопродление** (Булево) — автоматическое продление последней строки.
- **ПериодАвтопродления** (Число, секунд) — интервал автопродления (по умолчанию 300 сек = 5 мин).
- **Состояние** (перечисление) — Черновик, Активен, Завершён.
- **ИдентификаторПользователя** — ссылка на справочник Пользователи.

#### Табличная часть «Строки»
- **НомерСтроки** (Число) — порядок строки.
- **ВремяНачала** (Дата) — вычисляется: для первой = ВремяНачалаДня, для остальных = ВремяОкончания предыдущей.
- **ВремяОкончания** (Дата) — для всех кроме последней = ВремяНачала следующей; для последней — обновляется автоматически или вручную.
- **Задача** — ссылка на «ВнешниеЗадачи».
- **Комментарий** (Строка) — короткое описание работы.
- **ИдентификаторЗаписиВремени** (Строка) — ID записи времени во внешней системе, заполняется при синхронизации.

#### Вычисляемое поле формы строки
- **ТипСтроки** — определяется по Задача.ВнешняяСистема.ТипСистемы.ИмеетИнтеграцию:
  - Истина → «Рабочая» (синхронизируется)
  - Ложь → «Не синхронизируется» (Обед, локальная задача)

### 2.3 Константы подсистемы таймтрекинга
- **ЗадачаПоУмолчанию** — ссылка на элемент «ВнешниеЗадачи» для нераспределённого времени.
- **ЗадачаОбед** — ссылка на элемент «Обед».

## 3. Подсистемы и их взаимодействие

### 3.1 Подсистема «УчетРабочегоВремени»

#### Форма документа «ЛистУчетаРабочегоВремени»
- Создание/редактирование/завершение дня
- Обработчики формы: создание, автопродление, переключение задачи
- Серверные методы по обработке строк
- Индикаторы строк (синхронизировано / требуется синхронизация / не синхронизируется)

#### Модуль документа «ЛистУчетаРабочегоВремени»
- **СоздатьСтроку(Задача)** — создание новой строки с фиксацией времени окончания предыдущей
- **АвтопродлитьПоследнююСтроку()** — обновление ВремяОкончания последней активной строки
- **ЗавершитьДень()** — фиксация последнего интервала, перевод в состояние «Завершён»
- **СгруппироватьСтрокиДляСинхронизации()** → Массив групп строк для передачи в ФасадИнтеграции
  - Группирует последовательные строки с одинаковой задачей
  - Вычисляет суммарную длительность и итоговый комментарий для каждой группы

#### Взаимодействие с фасадом интеграции
- Документ не содержит HTTP-вызовов и не знает о конкретных внешних системах.
- Все операции синхронизации выполняются через `ФасадИнтеграции`.

### 3.2 ФасадИнтеграции (единая точка входа для всех внешних систем)

Единая точка входа для бизнес-логики работы с внешними системами. Делегирует вызовы конкретным API-модулям в зависимости от типа системы.

**Методы:**

1. **ПолучитьСписокЗадач(ТипВнешнейСистемы, ИдентификаторПользователя)** → ТаблицаЗначений
   - Возвращает список задач для заполнения выпадающего списка на форме
   - Внутри по типу системы вызывает соответствующий API-модуль

2. **ДобавитьЗаписьОВремени(ВнешняяЗадача, ДлительностьВСекундах, ДатаРаботы, Описание)** → ИдентификаторЗаписиВремени
   - Создаёт новую запись времени во внешней системе
   - Возвращает ID созданной записи

3. **ИзменитьЗаписьОВремени(ИдентификаторЗаписиВремени, Описание)** → ИдентификаторОбновленнойЗаписиВремени
   - Обновляет существующую запись времени (описание)
   - Для систем без нативной поддержки (например GitLab) — выполняет удаление и создание заново
   - Возвращает ID обновлённой записи

4. **УдалитьЗаписьОВремени(ИдентификаторЗаписиВремени)**
   - Удаляет существующую запись времени во внешней системе

5. **ПолучитьЗаписиОВремениЗаПериод(ВнешняяСистема, ДатаНач, ДатаКон, Задача)** → ТаблицаЗначений
   - Возвращает записи времени за указанный период
   - Используется формой «ТаймлогиGitLab»

6. **УдалитьЗаписиОВремениПоДате(ВнешняяЗадача, Дата)**
   - Удаляет все записи времени для задачи на указанную дату
   - Используется для идемпотентной синхронизации

### 3.3 Схема взаимодействия
```
[Форма документа ЛистУчетаРабочегоВремени]
    ↓ использует (группировка строк)
[Модуль документа «ЛистУчетаРабочегоВремени»]
    ↓ вызывает операции синхронизации
[ФасадИнтеграции]
    ↓ делегирует по типу системы
[API-модули внешних систем: GitLabAPI, JiraAPI и т.д.]
```

## 4. Алгоритм синхронизации

### 4.1 Подготовка данных
1. Вызвать `СгруппироватьСтрокиДляСинхронизации()` — получить группы последовательных строк с одинаковой задачей.
2. Для строк без задачи — подставить ЗадачуПоУмолчанию.

### 4.2 Группировка (в модуле документа)
1. Сгруппировать последовательные строки с одинаковой Задача.
2. Если между строками есть другая задача — группа прерывается.
3. Для каждой группы вычислить:
   - **СуммарнаяДлительность** = сумма (ВремяОкончания - ВремяНачала) всех строк.
   - **ИтоговыйКомментарий** = уникальные непустые комментарии, объединённые через «; ».

### 4.3 Создание/обновление записей времени
1. Для каждой группы определить `ДатаРаботы` = Дата документа + ВремяНачала первой строки.
2. Проверить ИдентификаторЗаписиВремени в строках группы:
   - Если заполнен и данные не изменились — пропустить группу.
   - Если изменился или пустой — вызвать `ФасадИнтеграции.УдалитьЗаписьОВремени(старый ID)`.
3. Вызвать `ФасадИнтеграции.ДобавитьЗаписьОВремени(Задача, Длительность, ДатаРаботы, Комментарий)`.
4. Записать новый ID во все строки группы.

### 4.4 Обновление описания записи
1. Если пользователь изменил комментарий в строке — вызвать `ФасадИнтеграции.ИзменитьЗаписьОВремени(ID, НовыйКомментарий)`.
2. При отсутствии нативной поддержки — выполнить удаление и создание заново через Фасад.

### 4.5 Обработка ошибок
- Если внешняя система недоступна — выдать сообщение, не сбрасывать идентификаторы.
- Строки с ошибкой помечаются жёлтым индикатором на форме.

## 5. Интерфейс работника

### 5.1 Создание дня
- Кнопка «Начать день» — создаётся документ на текущую дату, одна строка с ЗадачейПоУмолчанию.
- Документ переводится в состояние «Активен», запускается фоновое задание автопродления.

### 5.2 Автопродление последней строки
- Пока документ активен, раз в ПериодАвтопродления обновляется ВремяОкончания последней строки = ТекущаяДата().
- При переключении на другую задачу — текущая строка фиксируется.

### 5.3 Переключение задачи
- Горячая клавиша Ctrl+N — новая строка (переключение задачи).
- У текущей строки ВремяОкончания фиксируется = ТекущаяДата().
- Новая строка получает ВремяНачала = этому времени, ТипСтроки определяется автоматически.

### 5.4 Индикаторы строк на форме
- 🟢 Зелёный — синхронизировано и актуально.
- 🟡 Жёлтый — требуется синхронизация (идентификатор пуст или данные изменились).
- ⚪ Серый — не синхронизируется (Обед, локальная задача).

### 5.5 Завершение дня
- Кнопка «Завершить день» — фиксируется ВремяОкончания последней строки, состояние «Завершён».
- Автопродление останавливается.
- Доступна ручная правка строк и комментариев.
- Кнопка «Синхронизировать».

### 5.6 Выбор задачи
- Поле с выпадающим списком, динамически загружается при активации.
- Поиск по подстроке с запросом к Фасаду (по всем системам сразу).
- Часто используемые задачи кешируются на форме.

## 6. Расширяемость

Добавление новой внешней системы:
1. Новое значение в перечисление «ТипВнешнихСистем».
2. Новый модуль API (например, JiraAPI) с методами Добавить/Изменить/Удалить/ПолучитьЗаписиОВремени.
3. Регистрация диспетчеризации в ФасадИнтеграции.
4. Настройка подключения в регистре сведений «ВнешниеСистемы».

Работник продолжает пользоваться тем же интерфейсом.
