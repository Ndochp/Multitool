# Задачи на разработку подсистемы GitLab.mirror (TDD)

## Обзор

Данный документ содержит задачи на разработку подсистемы GitLab.mirror, сформированные по принципам Test-Driven Development (TDD). Каждая задача включает описание модуля/метода и соответствующие юнит-тесты.

---

## Задача GITL-004: GitLabAPI — Инициализация

**Модуль:** `ОбщийМодуль.GitLabAPI`  
**Методы:** `УстановитьБазовыйURL(БазовыйURL)`, `УстановитьТокен(Токен)`  
**Описание:** Настройка базового URL и токена аутентификации для GitLab API.

### Юнит-тесты

#### ТЕСТ-009: Установка базового URL
- **Дано:** Новый модуль GitLabAPI без настроек
- **Когда:** Вызван `УстановитьБазовыйURL("https://gitlab.example.com")`
- **То:** Базовый URL сохранён и используется при формировании запросов

#### ТЕСТ-010: Установка токена аутентификации
- **Дано:** Новый модуль GitLabAPI без настроек
- **Когда:** Вызван `УстановитьТокен("glpat-abc123")`
- **То:** Токен сохранён и используется в заголовке PRIVATE-TOKEN

#### ТЕСТ-011: Формирование URL с базовым URL
- **Дано:** Установлен БазовыйURL = "https://gitlab.example.com"
- **Когда:** Вызван метод, формирующий полный URL для эндпоинта "/api/v4/projects/1"
- **То:** Возвращается полный URL "https://gitlab.example.com/api/v4/projects/1"

## Задача GITL-005: GitLabAPI — ПолучитьНазначенныеЗадачи

**Модуль:** `ОбщийМодуль.GitLabAPI`  
**Метод:** `ПолучитьНазначенныеЗадачи(ИдентификаторПользователя, Состояние)`  
**Описание:** Получает список назначенных задач (Issues) пользователя через GitLab API.

### Юнит-тесты

#### ТЕСТ-012: Успешное получение списка задач
- **Дано:** Mock HTTP-сокета, возвращающий массив задач со статусом 200
- **Когда:** Вызван `ПолучитьНазначенныеЗадачи(42, "opened")`
- **То:** Возвращается ТаблицаЗначений с полями ID, IID, Title, WebURL, ProjectID

#### ТЕСТ-013: Пустой список задач
- **Дано:** Mock HTTP-сокета, возвращающий пустой массив `[]` со статусом 200
- **Когда:** Вызван `ПолучитьНазначенныеЗадачи(42, "opened")`
- **То:** Возвращается пустая ТаблицаЗначений

#### ТЕСТ-014: Формирование запроса с параметрами
- **Дано:** Mock HTTP-сокета, возвращающий массив задач со статусом 200
- **Когда:** Вызван `ПолучитьНазначенныеЗадачи(42, "opened")`
- **То:** Запрос отправлен на URL с параметрами `assignee_id=42&state=opened`

#### ТЕСТ-015: Обработка ошибки 404 при получении задач
- **Дано:** Mock HTTP-сокета, возвращающий ошибку 404 со статусом 404
- **Когда:** Вызван `ПолучитьНазначенныеЗадачи(999, "opened")`
- **То:** Генерируется исключение с сообщением о пользователе не найден

## Задача GITL-006: GitLabAPI — ДобавитьЗатраченноеВремя

**Модуль:** `ОбщийМодуль.GitLabAPI`  
**Метод:** `ДобавитьЗатраченноеВремя(ПроектID, IssueIID, ДлительностьВСекундах, ДатаРаботы, Описание)`  
**Описание:** Создаёт новую запись времени (timelog) в GitLab через POST /projects/:id/issues/:issue_iid/time_spent.

### Юнит-тесты

#### ТЕСТ-016: Успешное добавление timelog
- **Дано:** Mock HTTP-сокета, возвращающий JSON созданного timelog со статусом 201
- **Когда:** Вызван `ДобавитьЗатраченноеВремя(1, 42, 3600, "2024-01-15", "Работа над модулем")`
- **То:** Возвращается ID созданной записи (timelog_id из ответа)

#### ТЕСТ-017: Формирование тела запроса
- **Дано:** Mock HTTP-сокета, возвращающий JSON timelog со статусом 201
- **Когда:** Вызван `ДобавитьЗатраченноеВремя(1, 42, 3600, "2024-01-15", "Работа над модулем")`
- **То:** Тело запроса содержит duration="1h", spent_at="2024-01-15T00:00:00Z", summary="Работа над модулем"

#### ТЕСТ-018: Добавление timelog с нулевой длительностью
- **Дано:** Mock HTTP-сокета, возвращающий JSON timelog со статусом 201
- **Когда:** Вызван `ДобавитьЗатраченноеВремя(1, 42, 0, "2024-01-15", "Тест")`
- **То:** Возвращается ID созданной записи

#### ТЕСТ-019: Добавление timelog с некорректной датой
- **Дано:** Mock HTTP-сокета, возвращающий ошибку валидации со статусом 422
- **Когда:** Вызван `ДобавитьЗатраченноеВремя(1, 42, 3600, "2024-13-01", "Тест")`
- **То:** Генерируется исключение с сообщением о неверном формате даты

## Задача GITL-011: GitLabAPI — ПолучитьTimelogиПоСотруднику

**Модуль:** `ОбщийМодуль.GitLabAPI`  
**Метод:** `ПолучитьTimelogиПоСотруднику(ИдентификаторПользователя, ДатаНач, ДатаКон)`  
**Описание:** Получает все timelogs сотрудника за период через GET /api/v4/users/{user_id}/time_entries.

### Юнит-тесты

#### ТЕСТ-029: Успешное получение timelogs сотрудника
- **Дано:** Mock HTTP-сокета, возвращающий массив timelogs со статусом 200
- **Когда:** Вызван `ПолучитьTimelogиПоСотруднику(42, "2024-01-01", "2024-01-31")`
- **То:** Возвращается ТаблицаЗначений с полями timelog_id, project_name, issue_iid, issue_title, duration_seconds, spent_at, description, web_url

#### ТЕСТ-030: Формирование запроса к user time_entries
- **Дано:** Mock HTTP-сокета, возвращающий массив timelogs со статусом 200
- **Когда:** Вызван `ПолучитьTimelogиПоСотруднику(42, "2024-01-01", "2024-01-31")`
- **То:** Запрос отправлен на URL `/api/v4/users/42/time_entries?date_on_or_after=2024-01-01&date_before=2024-01-31`

#### ТЕСТ-031: Преобразование duration_seconds в часы
- **Дано:** Mock HTTP-сокета, возвращающий timelog с duration_seconds=5400 со статусом 200
- **Когда:** Вызван `ПолучитьTimelogиПоСотруднику(42, "2024-01-01", "2024-01-31")`
- **То:** В возвращённой таблице duration_seconds=5400 (90 минут)

## Задача GITL-014: Форма «ТаймлогиGitLab» — Поиск по дате и сотруднику

**Модуль:** `Форма.ТаймлогиGitLab`  
**Описание:** Форма для просмотра и управления таймлогами в GitLab.

### Юнит-тесты формы

#### ТЕСТ-036: Загрузка сотрудников в параметр отбора
- **Дано:** Пустая форма «ТаймлогиGitLab»
- **Когда:** Форма открывается
- **То:** Параметр «Сотрудник» заполняется списком сотрудников из справочника

#### ТЕСТ-037: Выполнение поиска по дате и сотруднику
- **Дано:** Форма открыта, параметры Сотрудник=42, ДатаНач="2024-01-01", ДатаКон="2024-01-31" заполнены
- **Когда:** Нажата кнопка «Выполнить поиск»
- **То:** Таблица результатов заполняется данными из `GitLabAPI.ПолучитьTimelogиПоСотруднику(42, "2024-01-01", "2024-01-31")`

#### ТЕСТ-038: Валидация обязательных параметров
- **Дано:** Форма открыта, параметр «Сотрудник» не заполнен
- **Когда:** Нажата кнопка «Выполнить поиск»
- **То:** Выводится сообщение об обязательном заполнении параметра «Сотрудник», таблица результатов пуста

#### ТЕСТ-039: Форматирование длительности в таблице результатов
- **Дано:** Таблица результатов содержит запись с duration_seconds=5400
- **Когда:** Форма отображается
- **То:** В колонке «Длительность» отображается "1ч 30мин" (или аналогичный человеко-читаемый формат)

#### ТЕСТ-040: Удаление выбранной записи
- **Дано:** Таблица результатов содержит строку с timelog_id=100, проект_идентификатор=1
- **Когда:** Строка выделена и нажата кнопка «Удалить выбранную запись», пользователь подтверждает
- **То:** Вызван `GitLabAPI.УдалитьTimelogПоID(100, 1)`, строка удалена из таблицы результатов

#### ТЕСТ-041: Открытие веб-страницы задачи
- **Дано:** Таблица результатов содержит строку с web_url="https://gitlab.example.com/project/-/issues/42"
- **Когда:** Строка выделена и нажата кнопка «Открыть веб-страницу задачи»
- **То:** Браузер открывает URL "https://gitlab.example.com/project/-/issues/42"

#### ТЕСТ-042: Экспорт в Excel
- **Дано:** Таблица результатов содержит данные
- **Когда:** Нажата кнопка «Экспорт в Excel»
- **То:** Сформирован табличный документ с данными из таблицы результатов, предложен для сохранения/открытия
